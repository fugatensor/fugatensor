# 03. 引擎与执行

<a id="engine-lifecycle"></a>

## 引擎创建与生命周期

```text
ft.Engine(device="cpu", *, ask_opt=None, cache_dir=None,
          compilers=None, llc=None, ptxas=None, cc="cc")
ft.configure(device="cpu", **options)
ft.shutdown(device=None)
```

`Engine` 管理编译缓存及设备资源。`device` 支持 `"cpu"`、`"cuda"`、`"cuda:N"`；`"cuda:0"` 规范化为 `"cuda"`。

| 参数 | 用途 |
| --- | --- |
| `cache_dir` | 产物与磁盘缓存目录；默认位于 `$XDG_CACHE_HOME/fugatensor`，未设环境变量时用 `~/.cache/fugatensor`。 |
| `llc`、`ptxas` | 自有 CUDA 代码生成工具的路径；CPU 不需要。 |
| `compilers` | 外部编译器环境映射；Triton 用 `{"triton": ft.triton.environment(...)}`。传空字典可禁用默认编译器配置。 |
| `cc` | CPU 目标文件的共享库链接器，默认 `cc`。 |
| `ask_opt` | 显式选择 CLI 兼容入口；默认直接调用 ASK C++ 编译库，不需要 `ask-opt`。 |

`ft.configure` 创建并返回对应设备的默认引擎；重新配置会关闭旧默认引擎，其 Tensor 随后不能继续使用。`ft.shutdown()` 关闭全部默认引擎，指定设备则只关闭该设备；显式创建的 Engine 由调用方负责关闭。

`with ft.Engine(...) as engine:` 在上下文中设定当前引擎，退出时关闭并恢复外层上下文。所有数据读取应在关闭前完成；`engine.close()` 可重复调用，CUDA 上会等待已提交任务。

```python
import fugatensor as ft

with ft.Engine("cpu") as engine:
    x = ft.tensor([1.0, 2.0])
    assert x.engine is engine
    assert (x + 1).tolist() == [2.0, 3.0]
assert engine.closed
```

<a id="execution"></a>

## 求值与同步

| 接口 | 返回值与行为 |
| --- | --- |
| `ft.evaluate(*tensors)` | 至少一个 Tensor。合并所需依赖图并求值；单输入返回原 Tensor，多输入返回由原 Tensor 组成的 tuple。所有 Tensor 必须属于同一引擎。 |
| `engine.evaluate(*tensors)` | 返回输入 Tensor 组成的 tuple；已计算结果不重复执行。 |
| `engine.synchronize()` | 等待已提交的 CUDA 工作，CPU 无设备等待；不会主动求值尚未提交的表达式。 |
| `engine.to_flat(tensor)` | 求值并返回展平的 Python list；CUDA 会下载数据。 |
| `engine.tensor(...)`、`engine.from_buffer(...)` | 显式绑定该引擎创建 Tensor，参数见[张量接口](01-张量与数据交换.md)。 |

CUDA 的 `evaluate` 提交计算后即可返回，读取 `tolist()` / `to_buffer()` 会等待结果。普通 Python 函数始终正常执行；编译缓存不会跳过用户的 Python 副作用。GPU JIT 通过原生桥使用 CUDA Graph replay，用户不需要自行捕获 Graph。

```python
import fugatensor as ft

with ft.Engine("cpu") as engine:
    x = ft.tensor([2.0, 3.0])
    y, z = x * x, x + 1
    result = ft.evaluate(y, z)
    assert result[0] is y and result[1] is z
    engine.synchronize()
    assert y.tolist() == [4.0, 9.0]
    assert z.tolist() == [3.0, 4.0]
```

<a id="cache-and-diagnostics"></a>

## 缓存与诊断

| 接口 | 内容 |
| --- | --- |
| `engine.cache_info()` | `compilations`、`cache_hits` 累计计数，以及当前 `specializations` 数量。 |
| `engine.clear_cache()` | 清除引擎已编译图及最近诊断信息；不重置累计计数、不删除磁盘缓存、不使已计算 Tensor 失效。 |
| `engine.stats` | 编译、执行和命中统计；CUDA 会话创建后额外包含 `runtime` 统计，包括 `graph_launches`、`graph_instantiations` 等。 |
| `engine.last_fuga_ir` | 最近实际求值图的 Fuga IR 文本。 |
| `engine.last_ask_ir` / `last_ir` | 对应的 ASK MLIR 文本，两个名字表示同一内容。 |
| `engine.last_report` / `last_artifact_dir` | 编译报告 dict 与产物目录 Path；尚无执行或刚清缓存时为 `None`。 |
| `engine.closed` | 是否已经关闭。 |
| `engine.capability` | CUDA 设备的 `(major, minor)`；会触发会话创建，CPU 引擎访问时报错。 |
| `engine.session` | CUDA 会话调试入口，惰性创建；返回的后端对象不属于可移植 Tensor 接口。 |

配置读取顺序通常为显式参数、环境变量、可选 `engine.json`。显式指定 `ask_opt` 时会隔离默认文件中的工具与 worker 配置；`cc` 只通过参数传入。支持的环境变量和配置文件格式统一见[引擎配置](../architecture/04-ASK桥接与多后端执行.md#bootstrap-and-config)。
