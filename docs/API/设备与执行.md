# 设备与执行

张量默认创建在 CPU 上，类型为 `ft.fp32`。框架按设备创建和复用引擎。

<a id="default-device"></a>

## 选择设备

| 接口 | 返回值与行为 |
| --- | --- |
| `ft.device(type, index=None)` | 创建不可变设备描述，如 `ft.device("cpu")`、`ft.device("cuda:0")`、`ft.device("cuda", 0)`。 |
| `ft.set_default_device(device)` | 返回 `None`，设置当前 Python 上下文中后续张量的默认设备。已有张量和引擎保持原设备，GPU 在实际使用时初始化。 |
| `ft.get_default_device()` | 返回当前有效的默认设备对象。 |
| `ft.tensor(..., device=...)` | 仅为此次创建选择设备，覆盖默认值；`from_buffer`、`load_weights` 同样支持。 |

所有 `device=` 参数接受设备对象或字符串。对象的 `.type` 为 `"cpu"` 或 `"cuda"`，`.index` 为设备编号或 `None`。Tensor 的 `.device` 返回实际设备：CPU 不带编号，未指定编号的 CUDA 解析为 `cuda:0`。默认设备由 `ContextVar` 保存，各独立线程和异步任务上下文分别设置。

```python
import fugatensor as ft

cpu = ft.device("cpu")
x = ft.tensor([1, 2, 3], device=cpu)
print(x.device.type, x.device.index)  # cpu None
print((x * 2 + 1).tolist())           # [3.0, 5.0, 7.0]
```

以下例子需要已配置的 CUDA 环境：

```python
import fugatensor as ft

ft.set_default_device(ft.device("cuda", 0))
x = ft.tensor([1, 2, 3])
print((x + 1).tolist())  # [2.0, 3.0, 4.0]
cpu = ft.tensor([4, 5, 6], device="cpu")
ft.set_default_device("cpu")
print(x.device)         # cuda:0，已有张量仍留在原设备
```

不同设备的 Tensor 混合运算报 `RuntimeError`；同设备但属于不同 Engine 报 `ValueError`。

<a id="execution"></a>

## 求值与同步

| 接口 | 返回值与行为 |
| --- | --- |
| `ft.evaluate(*tensors)` | 至少一个 Tensor，合并依赖图并求值。单输入返回原 Tensor，多输入返回原 Tensor 组成的 tuple；须属于同一引擎。 |
| `ft.synchronize(device=None)` | 返回 `None`，等待所选引擎已提交的工作；省略设备时使用当前默认选择，CPU 无设备等待。不会主动求值尚未提交的表达式。 |
| `x.tolist()` / `x.to_buffer()` | 按需执行并取回结果，CUDA 上会等待计算和主机传输。 |

CUDA 的 `evaluate` 提交后即可返回，读取结果或调用 `ft.synchronize("cuda")` 时等待完成。编译结果按图结构缓存，Python 函数仍逐次执行。GPU JIT 使用 CUDA Graph replay。

```python
import fugatensor as ft

x = ft.tensor([2, 3])
y, z = x * x, x + 1
ft.evaluate(y, z)
print(y.tolist(), z.tolist())  # [4.0, 9.0] [3.0, 4.0]
```

<a id="configuration"></a>

## 可选配置

`ft.configure(device="cpu", **options)` 设置工具路径、缓存目录和外部编译环境，返回该设备的默认 `Engine`。在创建张量前调用；重新配置会关闭旧默认引擎，并使其 Tensor 失效。默认设备仍由 `set_default_device` 设置。

| 参数 | 用途 |
| --- | --- |
| `cache_dir` | 产物与磁盘缓存目录；默认 `$XDG_CACHE_HOME/fugatensor`，未设环境变量时为 `~/.cache/fugatensor`。 |
| `llc`、`ptxas` | 自有 CUDA 代码生成工具路径。 |
| `compilers` | 外部编译器环境映射，例如 `{"triton": ft.triton.environment(...)}`；空字典禁用默认编译器配置。 |
| `cc` | CPU 共享库链接器，默认 `"cc"`。 |
| `ask_opt` | 选择 `ask-opt` CLI 入口；默认调用 ASK C++ 编译库。 |

配置按参数、环境变量、`engine.json` 的顺序取值。CUDA 引擎在未配置 worker 时使用当前 Python 环境已安装的 Triton。指定 `ask_opt` 会隔离默认文件中的工具和 worker；`cc` 通过参数传入。配置文件格式见[引擎配置](../architecture/ASK桥接与多后端执行.md#bootstrap-and-config)。

<a id="cache-and-diagnostics"></a>

## 查看缓存和执行信息

通过 `x.engine` 查看引擎的缓存与最近一次执行：

| 接口 | 内容 |
| --- | --- |
| `engine.cache_info()` | `compilations`、`cache_hits` 累计计数及当前 `specializations` 数量。 |
| `engine.clear_cache()` | 清除已编译图及最近诊断，不重置累计计数、不删除磁盘缓存、不使已计算 Tensor 失效。 |
| `engine.stats` | 编译、执行和命中统计；CUDA 会话创建后额外包含 `runtime`，如 `graph_launches`、`graph_instantiations`。 |
| `engine.last_fuga_ir` | 最近实际求值图的 Fuga IR 文本。 |
| `engine.last_ask_ir` / `last_ir` | 对应的 ASK MLIR 文本，两个名字表示同一内容。 |
| `engine.last_report` / `last_artifact_dir` | 编译报告 dict 与产物目录 Path；尚无执行或刚清缓存时为 `None`。 |

<a id="engine-lifecycle"></a>

## 高级用法：独立引擎与资源释放

默认引擎在正常进程退出时关闭，并等待已提交任务。调用 `ft.shutdown(device=None)` 可提前释放：省略设备关闭全部默认引擎，指定设备则只关闭对应引擎。函数返回 `None`，保留默认设备选择。旧 Tensor 随引擎关闭失效，下次创建张量时重建引擎。

用独立引擎设置单独的缓存和资源寿命：

```text
ft.Engine(device="cpu", *, ask_opt=None, cache_dir=None,
          compilers=None, llc=None, ptxas=None, cc="cc")
```

参数同 `configure`。用 `engine.tensor(...)`、`engine.from_buffer(...)` 或 `ft.tensor(..., engine=engine)` 绑定引擎。`with ft.Engine(...) as engine:` 临时选择该引擎，退出时关闭并恢复外层上下文。`device=` 可另选设备；同时传入 `engine` 时须与其设备一致。跨引擎 Tensor 混合运算会报错。

| 高级接口 | 行为 |
| --- | --- |
| `engine.evaluate(*tensors)` | 返回输入 Tensor 组成的 tuple，已计算结果不重复执行。 |
| `engine.synchronize()` | 只等待此引擎已提交的工作，包括独立引擎的 CUDA 会话。 |
| `engine.to_flat(tensor)` | 求值后返回展平的 Python list；CUDA 会下载数据。 |
| `engine.close()` / `engine.closed` | 关闭引擎 / 查询是否关闭；`close()` 可重复调用，CUDA 上会等待已提交任务。 |
| `engine.capability` | CUDA 的 `(major, minor)`；会触发会话创建，CPU 访问时报错。 |
| `engine.session` | CUDA 会话调试入口，惰性创建；后端对象不属于可移植 Tensor API。 |

独立引擎由调用方关闭，数据应在关闭前读取。`ft.shutdown` 只管理默认引擎。
