# 设备与执行

普通程序直接调用 `ft.tensor(...)`，无需创建 `Engine` 或使用 `with`。框架按设备惰性创建并复用执行资源；默认设备为 CPU，默认类型为 `ft.fp32`。

<a id="default-device"></a>

## 选择设备

| 接口 | 返回值与行为 |
| --- | --- |
| `ft.device(type, index=None)` | 创建不可变设备对象，如 `ft.device("cpu")`、`ft.device("cuda:0")`、`ft.device("cuda", 0)`；不初始化设备。 |
| `ft.set_default_device(device)` | 返回 `None`，设置当前 Python 上下文中后续创建张量的默认设备；不初始化 GPU、不移动现有张量、不关闭已有引擎。 |
| `ft.get_default_device()` | 返回当前有效默认设备对象；不创建引擎。 |
| `ft.tensor(..., device=...)` | 仅为此次创建选择设备，覆盖默认值；`from_buffer`、`load_weights` 同样支持。 |

所有 `device=` 参数接受设备对象或字符串。对象的 `.type` 为 `"cpu"` 或 `"cuda"`，`.index` 为设备编号或 `None`。Tensor 的 `.device` 返回实际设备：CPU 不带编号，未指定编号的 CUDA 解析为 `cuda:0`。默认设备使用 `ContextVar` 保存，修改不会串到其他独立线程或异步任务的上下文；已有张量保持原设备。

```python
import fugatensor as ft

cpu = ft.device("cpu")
x = ft.tensor([1, 2, 3], device=cpu)
print(x.device.type, x.device.index)  # cpu None
print((x * 2 + 1).tolist())           # [3.0, 5.0, 7.0]
```

以下例子需要已配置的 CUDA 环境：

```python
import fugatensor as ft

ft.set_default_device(ft.device("cuda", 0))
x = ft.tensor([1, 2, 3])
print((x + 1).tolist())  # [2.0, 3.0, 4.0]
cpu = ft.tensor([4, 5, 6], device="cpu")
ft.set_default_device("cpu")
print(x.device)         # cuda:0，已有张量仍留在原设备
```

不同设备的 Tensor 参与同一次运算会抛出 `RuntimeError`，不会自动搬运数据；同设备但属于不同独立 Engine 的 Tensor 混用时抛出 `ValueError`。

<a id="execution"></a>

## 求值与同步

| 接口 | 返回值与行为 |
| --- | --- |
| `ft.evaluate(*tensors)` | 至少一个 Tensor，合并依赖图并求值。单输入返回原 Tensor，多输入返回原 Tensor 组成的 tuple；须属于同一引擎。 |
| `ft.synchronize(device=None)` | 返回 `None`，等待所选引擎已提交的工作；省略设备时使用当前默认选择，CPU 无设备等待。不会主动求值尚未提交的表达式。 |
| `x.tolist()` / `x.to_buffer()` | 按需执行并取回结果，CUDA 上会等待计算和主机传输。 |

CUDA 的 `evaluate` 提交计算后即可返回。需要同步时可指定 `ft.synchronize("cuda")`；通常读取结果就足够。普通 Python 函数始终正常执行，编译缓存不会跳过 Python 副作用；GPU JIT 自动使用 CUDA Graph replay。

```python
import fugatensor as ft

x = ft.tensor([2, 3])
y, z = x * x, x + 1
ft.evaluate(y, z)
print(y.tolist(), z.tolist())  # [4.0, 9.0] [3.0, 4.0]
```

<a id="configuration"></a>

## 可选配置

`ft.configure(device="cpu", **options)` 用于设置工具路径、缓存目录或外部编译环境，返回该设备的默认 `Engine`。环境已配置时不必调用；它只配置指定设备，不改变 `set_default_device` 的选择。应在创建张量前配置，重新配置会关闭该设备的旧默认引擎，使其 Tensor 失效。

| 参数 | 用途 |
| --- | --- |
| `cache_dir` | 产物与磁盘缓存目录；默认 `$XDG_CACHE_HOME/fugatensor`，未设环境变量时为 `~/.cache/fugatensor`。 |
| `llc`、`ptxas` | 自有 CUDA 代码生成工具路径，CPU 不需要。 |
| `compilers` | 外部编译器环境映射，例如 `{"triton": ft.triton.environment(...)}`；空字典禁用默认编译器配置。 |
| `cc` | CPU 共享库链接器，默认 `"cc"`。 |
| `ask_opt` | 显式选择 CLI 兼容入口；默认直接调用 ASK C++ 编译库，无需 `ask-opt`。 |

工具配置优先级为显式参数、环境变量、可选 `engine.json`；没有 Triton worker 配置时，CUDA 引擎再尝试使用当前 Python 环境已安装的 Triton。显式指定 `ask_opt` 时隔离默认文件中的工具与 worker 配置；`cc` 只通过参数传入。完整格式见[引擎配置](../architecture/ASK桥接与多后端执行.md#bootstrap-and-config)。

<a id="cache-and-diagnostics"></a>

## 查看缓存和执行信息

需要诊断时，从现有 Tensor 的 `x.engine` 取得引擎，无需改变普通计算代码：

| 接口 | 内容 |
| --- | --- |
| `engine.cache_info()` | `compilations`、`cache_hits` 累计计数及当前 `specializations` 数量。 |
| `engine.clear_cache()` | 清除已编译图及最近诊断，不重置累计计数、不删除磁盘缓存、不使已计算 Tensor 失效。 |
| `engine.stats` | 编译、执行和命中统计；CUDA 会话创建后额外包含 `runtime`，如 `graph_launches`、`graph_instantiations`。 |
| `engine.last_fuga_ir` | 最近实际求值图的 Fuga IR 文本。 |
| `engine.last_ask_ir` / `last_ir` | 对应的 ASK MLIR 文本，两个名字表示同一内容。 |
| `engine.last_report` / `last_artifact_dir` | 编译报告 dict 与产物目录 Path；尚无执行或刚清缓存时为 `None`。 |

<a id="engine-lifecycle"></a>

## 高级用法：独立引擎与资源释放

默认引擎在正常进程退出时自动关闭并等待已提交任务，不必在脚本末尾手动清理。长期进程需要提前释放资源时，可以调用 `ft.shutdown(device=None)`；省略设备关闭全部默认引擎，否则只关闭指定设备。它返回 `None`，不改变默认设备选择；旧 Tensor 随引擎关闭失效，下次创建会重新建立引擎。

需要独立缓存或明确限定资源寿命时，可显式创建引擎：

```text
ft.Engine(device="cpu", *, ask_opt=None, cache_dir=None,
          compilers=None, llc=None, ptxas=None, cc="cc")
```

参数含义同 `configure`。`engine.tensor(...)`、`engine.from_buffer(...)` 或 `ft.tensor(..., engine=engine)` 显式绑定引擎；也可通过 `with ft.Engine(...) as engine:` 临时选择它。该上下文优先于默认设备，退出时关闭并恢复外层上下文；显式 `device=` 仍可选择其他设备。两者同时指定时，`engine` 与 `device` 必须匹配。跨引擎 Tensor 不能直接混合运算。

| 高级接口 | 行为 |
| --- | --- |
| `engine.evaluate(*tensors)` | 返回输入 Tensor 组成的 tuple，已计算结果不重复执行。 |
| `engine.synchronize()` | 只等待此引擎已提交的工作，包括独立引擎的 CUDA 会话。 |
| `engine.to_flat(tensor)` | 求值后返回展平的 Python list；CUDA 会下载数据。 |
| `engine.close()` / `engine.closed` | 关闭引擎 / 查询是否关闭；`close()` 可重复调用，CUDA 上会等待已提交任务。 |
| `engine.capability` | CUDA 的 `(major, minor)`；会触发会话创建，CPU 访问时报错。 |
| `engine.session` | CUDA 会话调试入口，惰性创建；后端对象不属于可移植 Tensor API。 |

`ft.shutdown` 和退出清理只管理默认引擎。显式创建的独立引擎由调用方关闭，数据读取须在关闭之前完成。
