# 原生节点池与增量指纹优化

2026-11-04。本轮将 TraceTensor、待计算图及内置原语的热绑定迁入 C++，最终测量对应 Fuga `54c7698`；ASK 使用 `266e5e7`，编译器与运行时实现保持同一版本。

large CUDA 归约链的构图耗时 **353.245 → 87.933 μs，下降 75.11%**，低于提出的 80% 目标。同一分层口径下，包含释放的完整生命周期 **610.053 → 229.379 μs**。正式对照与内存结果分别列在后文。

<a id="implementation"></a>

## 节点与调用边界

`TraceTensor` 和 `Tensor` 使用原生扩展薄壳，持有上下文或 Engine 与 `uint32_t` 值编号。节点、表达式和输入边放在 C++ 连续数组中；运行时池按需增长，并复用容量与空闲槽。运行时值记录为 24 字节，表达式记录为 40 字节，输入边为 4 字节。编译期断言检查节点记录的 `is_trivial` 和 `standard_layout`。

对 Python 可见的张量仍各有一个薄壳。内部输入边直接引用节点编号，替代 Python Expression、Result、Alias 对象组成的持久图。运行时节点引用归零后迭代释放并复用槽位，已物化结果保留原生求导来源；追踪节点随 TraceArena 整体释放。模板、类型和存储资源位于独立表中，用户回调形成的 Python 引用环通过原生 GC 遍历参与回收。

内置原语的类型签名、静态参数编码和模板查找在 C++ 完成。命中后直接传递值编号并追加节点，单输出直接返回薄壳；普通 Python 函数仍按调用执行。归约轴和默认广播维度在模板首次准备时规范化。隔离追踪沿用 Fuga 的抽象类型与微分规则，节点先写入原生 arena，追踪结束时导出 Python IR。缓存未命中时的图组合及自动微分继续使用独立 Fuga IR，ASK 接口保持原有职责。

<a id="fingerprint"></a>

## 增量指纹与精确缓存键

节点创建时，将模板指纹与有序输入指纹合并，缓存本节点摘要。收集时将有序根指纹与活跃定义合成键摘要，`PlanKey.__hash__` 只读取已保存的键摘要；相等判断比较规范化的叶子类型、节点连接、输出顺序和定义身份。自然哈希碰撞测试使用整数常量 `-1` 与 `-2`，确认相同指纹的不同图分别编译并返回各自结果。

物化会改变数值输入边界。arena 版本随物化更新，已有下游节点在收集时按当前存储边界刷新摘要；多输出图按实际请求的投影建立键。热收集操作原生编号，绑定本次输入并校验活跃定义。`describe_pending` 仅在缓存未命中时创建用于拼接 IR 的表达式视图。

取指纹为常数时间，精确键构造、必要的图收集与相等比较仍随图规模增长。节点创建的摘要合并成本与本节点的输入数相关。分层测量同时记录构图、求值与释放，检查工作是否只是在阶段间移动。

## 测量方法

基线为 Fuga `bb4cf79`，与本轮使用相同 ASK 共享库。两个框架共用 Python 3.12.15，CPU 为 Xeon E5-2696 v4，GPU 为 RTX 3080，环境为 WSL2，Torch 为 2.14.0+cu130。正式 CPU 对照单线程并固定核心 2，正式 CUDA 对照沿用进程默认宿主亲和性；分层测量的 CPU/CUDA 宿主线程都固定核心 2。各自按相同设置前后比较，性能测量期间暂停构建和测试负载。

正式对照复用 `tools/benchmark_torch.py`：CPU/CUDA × 四类负载 × small/large × Fuga/Torch eager，重复三轮，共 96 项。每项独立进程与缓存，预热 10 次，记录 41 个热样本；输入创建位于计时外，CUDA 调用包含同步。首次编译和首次执行单独记录。

分层测量每项先校验一次、预热 5 次，再采集 31 次连续且不重叠的构图、求值、同步、释放区间。随后用临时包装器单独采集 31 次图收集、缓存查找与执行入口时间。正式整体延迟使用无插桩结果，诊断区间用于定位开销。另按图深度和输入叶子数扩展，检查原生收集与查找的增长趋势。

对“构图减少 80%”的检验使用构图自身耗时。本轮基线 large CUDA 归约链的三轮构图中位数为 353.245 μs，对应目标为 70.649 μs。

## CUDA matmul 交替复测

围绕正式对照的变慢项，使用同一冻结负载与计时包装，分别在默认宿主亲和性、固定核心 2 下交替运行基线和新版。每种设置重复五轮，共 20 个独立进程；每项预热 10 次、采样 41 次，全部数值正确，编译 1 次、执行 52 次。

| 宿主亲和性 | 基线中位数 [轮间范围] μs | 新版中位数 [轮间范围] μs |
| --- | ---: | ---: |
| 默认 | 161.598 [157.414, 190.360] | 157.569 [118.088, 165.594] |
| 核心 2 | 123.991 [121.866, 131.476] | 107.033 [106.362, 112.083] |

默认亲和性的五个配对中，四次新版更快，一次接近持平；固定核心的五次均更快。固定核心的独立分层测量中，matmul 构图为 24.864 → 11.720 μs，完整调用为 130.595 → 111.629 μs。复测没有重现一致退化，默认亲和性下的结果波动明显；这些数据不足以将正式退化唯一归因于宿主调度。

构图减少 75.11%，图收集与键构造减少 57.06%，缓存查找减少 79.87%；包含释放的生命周期减少 62.40%。主要收益来自前端。`Engine._execute` 的插桩区间包含绑定、ASK 调用和完成处理，代表执行入口成本；GPU 计算与同步的关系以完整调用为准。

## 对象内存与生命周期

寿命实验按深度 8/128 × 保留结果 0/4 × 待计算/已求值生成八项。每版构造 8880 张新图，记录 128 个快照，并检查弱引用、已保留结果的值和梯度、Engine 销毁。

同时保留 100 张、每张 128 层的待计算图时，内存增量相对同进程预热后、已释放构图结果的快照：

| 指标 | 基线 | 新版 |
| --- | ---: | ---: |
| Python Tensor 对象 | 12900 | 200 |
| tracemalloc 当前 Python 分配增量 | 4,355,480 B | 84,713 B |
| 原生节点池保留容量 | — | 1,048,576 B |
| 原生输入边池保留容量 | — | 131,072 B |
| 进程 RSS 增量 | 13,127,680 B | 1,507,328 B |
| tracemalloc 自身内存增量 | 4,697,664 B | 66,720 B |

Python 分配减少 98.06%。原生节点与边另占 1.125 MiB 保留容量；静态元信息、编译计划与存储资源另计。RSS 包含采样器与分配器行为，上表将采样器内存单列，避免把 Python 分配降幅解释为总内存降幅。

Engine 存活时连续十批构图的节点、边、依赖、模板、投影、精确键及池容量保持稳定。释放全部根后活跃节点、边、依赖归零，池容量保留供下一轮复用。关闭并销毁 Engine 后弱引用失效。原始数据的 `engine_closed` 行中，原生池计数取自关闭后、删除 Engine 前；Python 对象和进程内存在销毁后采集。

正式对照的同配置 GPU 峰值保留显存与 CPU 工作区在前后两版相同；本轮内存收益主要是宿主图对象。[基线快照](assets/native-arena-optimization/lifetime-baseline/raw.csv) · [新版快照](assets/native-arena-optimization/lifetime-final/raw.csv) · [寿命与数值检查](assets/native-arena-optimization/lifetime-final/metadata.json)。

## 构建、验证与复现

Fuga 的 Python 3.12 性能环境和 Python 3.13 开发环境均从最终代码重新构建。ASK core 构建确认产物为最新；ASK SDK、基线和两个 Fuga 环境中的编译器、运行时共享库 SHA-256 分别一致，完整记录见[构建来源](assets/native-arena-optimization/final-provenance.json)。

专项回归共 33 个方法通过：节点池、输入绑定、投影缓存、来源保留、求导、临时函数回收、并发冷构图、原语参数与公开数值契约。正交组合及独立参考见[测试矩阵](测试.md#native-arena-matrix)。

完整 CPU/CUDA/Triton 首轮运行 211 个方法，耗时 1662.183 秒：210 个通过，无跳过；剩余一个方法的两个子用例使用旧测试桩，从 `Module` 错误读取 `.module`。同步测试桩后，Triton 注册与 worker 契约的 9 个方法全部通过，包含该方法的两个子用例。修复仅涉及测试，生产代码与性能测量版本一致；完整套件随后未重复运行。
