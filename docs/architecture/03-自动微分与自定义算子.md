# 03. 自动微分与自定义算子

返回架构总览：[运行时自动微分、`ft.fun` 与高阶求导](README.md#arch-autodiff) · 相关细节：[张量模型与追踪机制](01-张量模型与追踪机制.md) · [原生图分析与 C++ 边界](02-原生图分析与C++边界.md) · [控制流与可组合变换](../ir/02-控制流与可组合变换.md)

前端通过 `requires_grad=True`、`y.backward()` 与 `x.grad` 驱动自动微分；每一段反向计算均通过 Fuga IR 的 `vjp` 变换生成静态反向图，再交由 ASK 编译为原生 CPU 或 GPU 代码执行。

<a id="runtime-autograd"></a>

## 1. 运行时 `GradHistory` 与反向调度（`autograd.py`）

在 `ft.no_grad()` 之外，编译后的静态片段（完整单图函数或 [Graph Break](01-张量模型与追踪机制.md#graph-break) 切出的片段）完成正向执行时：

1. **挂载历史节点**：若输入含 `requires_grad=True` 的浮点张量，运行时创建 `_BackwardNode`，记录该片段的 Fuga IR `Module` 副本、正向输入张量快照（记录底层存储的 `_version` 版本号以检测原地修改）及各输入张量的上游 `GradHistory`。输出张量通过 `(node, output_index)` 引用产生它的节点。
2. **输出梯度种子**：调用 `y.backward(grad=None, retain_graph=False, create_graph=False)` 时：
   - `y` 为 0-D 标量且省略 `grad` 时，自动生成同设备、同精度的标量 `1.0`；
   - `y` 为非标量张量时，必须显式传入同 shape、同 dtype、同 Engine 的 `grad` 种子，不做隐式求和。
3. **逆拓扑回传与叶子累加**：调度器收集从根输出可达的全部 `_BackwardNode` 按拓扑逆序遍历：
   - 对每个节点找出收到非空余切种子的输出端口，调用 [`project_outputs`](02-原生图分析与C++边界.md#transforms-reuse) 移除无关输出分支，再调用 [`ir.vjp(...)`](../ir/02-控制流与可组合变换.md#jvp-and-vjp) 生成反向 Fuga IR 模块并通过 ASK 编译执行；
   - 算出的输入梯度累加到上游节点或叶子张量的 `.grad` 上（多路梯度累加同样通过 `@ft.jit` 加法执行）。
4. **图生命周期**：默认一次 `backward()` 完成后释放沿途保存的张量与历史引用（再次调用 `backward()` 会报错）；设置 `retain_graph=True` 或 `create_graph=True` 时保留历史。`x.detach()` 返回共享底层存储但不带历史的新张量，`x.zero_grad()` 清空 `.grad`。

<a id="custom-fun"></a>

## 2. `ft.fun` 自定义前向与反向（`function.py`）

需要自定义梯度公式或为外部 Triton 算子提供反向实现时，继承 `ft.fun`：

```python
class ScaleAndSquare(ft.fun):
    @ft.jit
    def forward(self, ctx, x):
        ctx.save_for_backward(x)
        return ft.square(x)

    @ft.jit
    def backward(self, ctx, dy):
        (x,) = ctx.saved_tensors
        return (2 * x * dy,)
```

- **封闭追踪与 `fuga.call`**：`forward` 和提供的 `backward` 均须添加 `@ft.jit`。外层图调用 `op(x)` 时，单独追踪子函数体存入 `Module.metadata["functions"][callee]`，并在外层插入 `fuga.call` 指令。
- **SSA 保存通道**：`ctx.save_for_backward(...)` 保存的中间张量作为 `fuga.call` 额外的 `saved` SSA 输出端口显式传给 `vjp` 阶段，使死代码消除和缓存能感知其依赖。
- **反向展开**：`vjp` 阶段追踪 `backward(ctx, dy)`（支持单输出或 tuple 多输出余切，并校验返回的梯度 tuple 长度及各浮点输入的 shape/dtype）。`backward` 中同样可以调用 [`ft.triton.kernel`](04-ASK桥接与多后端执行.md#cuda-and-triton) 注册的 GPU 反向算子；引擎层会裁剪未使用的物理输入端口，因此仅依赖 `dy` 的单输入 Triton 反向 kernel 也能满足单端口融合要求。

<a id="higher-order"></a>

## 3. 基于 JVP / VJP 闭合的高阶自动微分

基础算子 `constant`、`splat`、`add`、`mul`、`cast` 的前向微分规则（`jvp`）和反向伴随规则（`vjp`）产出的指令仍全部属于这五种基础算子（例如乘法的 `vjp` 生成两条 `fuga.mul`，余切累加生成 `fuga.add`，可微浮点间的 `cast` 生成反向 `fuga.cast`）。

开启 `y.backward(create_graph=True)` 时，每一段反向 VJP 模块作为普通 `@ft.jit` 计算执行，算出的 `x.grad` 自身也会挂载记录反向计算图的 `GradHistory`。先执行 `x.zero_grad()` 再对 `x.grad` 调用 `.backward()`，即可对该反向图继续应用 `vjp` 并由 ASK 编译执行，从而计算二阶、三阶导数。

<a id="preflight-validation"></a>

## 4. 反向预检（Preflight Validation）

遇到未提供 `ft.fun.backward` 的裸 `fuga.external`，或对包含不透明 Triton 正向/反向的 `ft.fun` 请求二阶及以上导数时，必须在启动反向执行和改写任何叶子 `.grad` 之前拒绝。

`autograd.py` 在编译执行任何反向节点前，先对整张反向拓扑图执行一轮只读预检：

1. 根据 C++ [`analyze_function`](02-原生图分析与C++边界.md#native-analyze) 返回的 `reverse_ops` 定位实际处于当前求导路径上的算子（未连接到目标输出的旁路 `fuga.external` 不受影响）；
2. 预先构建各节点的 `vjp` 模块；若裸 `fuga.external` 缺少反向规则，或 `create_graph=True` 产出的梯度图依赖无原语规则的不透明外部算子，直接抛出 `TypeError` / `ValueError`；
3. 全部节点的反向 IR 通过构建与校验后，才开始编译执行并更新叶子 `.grad`。
