# 03. 自动微分与自定义算子

返回架构总览：[运行时自动微分、`ft.fun` 与高阶求导](README.md#arch-autodiff) · 相关细节：[张量模型与追踪机制](01-张量模型与追踪机制.md) · [原生图分析与 C++ 边界](02-原生图分析与C++边界.md) · [控制流与可组合变换](../ir/02-控制流与可组合变换.md)

FugaTensor 的自动微分把“**符合直觉的命令式前端**”与“**基于编译器的结构化 IR 微分**”结合在了一起：用户用熟悉的 `x = ft.tensor(..., requires_grad=True)`、`y.backward()` 和 `x.grad` 驱动求导，而水下每一段反向传播都不是在 Python 里逐算子解释执行，而是经过 Fuga IR 的 `vjp` 变换生成静态反向图，再交由 ASK 编译为原生 CPU 或 GPU 代码。

<a id="runtime-autograd"></a>

## 1. 运行时 `GradHistory` 与反向拼装（`autograd.py`）

在未进入 `with ft.no_grad():` 的上下文中，每当一段编译好的静态片段（无论是完整单图函数，还是 [Graph Break](01-张量模型与追踪机制.md#graph-break) 切出的一小段）完成正向执行时：

1. **挂载历史节点**：只要输入中存在 `requires_grad=True` 的浮点张量，运行时就会创建一个 `_BackwardNode`，记录该片段未经有损展开的 **Fuga IR `Module` 副本**、正向真实输入张量快照（用于提供诸如 `x * y` 反向所需的正向激活值，同时附上缓冲区的 `_version` 版本号防原地篡改）以及每个输入张量的上游 `GradHistory`。输出张量通过 `(node, output_index)` 指向自己的产生位置。
2. **显式种子约定**：调用 `y.backward(grad=None, retain_graph=False, create_graph=False)` 时：
   - 若 `y` 是 0-D 标量且省略 `grad`，默认注入同设备、同精度的标量 `1.0`；
   - 若 `y` 是非标量张量，**必须显式传入同 shape、同 dtype、同 Engine 的 `grad` 种子**——框架绝不偷偷对非标量输出做隐式求和。
3. **逆拓扑回传与叶子累加**：调度器收集从根输出可达的全部 `_BackwardNode` 按拓扑逆序遍历：
   - 对每个节点，先找出本次真正收到非空余切种子（cotangent）的输出端口，调用 [`project_outputs`](02-原生图分析与C++边界.md#transforms-reuse) 剪掉无关输出分支，再调用 [`ir.vjp(...)`](../ir/02-控制流与可组合变换.md#jvp-and-vjp) 生成对应的反向 Fuga IR 模块并通过 ASK 编译执行；
   - 算出的输入梯度继续累加到上游节点或叶子张量的 `.grad` 上（多路汇聚通过 JIT 编译的加法累加，绝不在主机侧绕道计算）。
4. **生命周期管理**：默认一次 `backward()` 完成后立即清空沿途节点的保存张量与历史引用，及时释放显存/内存（再次反向会明确报错）；传入 `retain_graph=True` 或 `create_graph=True` 时则保留历史供多次求导。`x.detach()` 返回共享底层存储但不带历史的新视图，`x.zero_grad()` 清空叶子 `.grad`。

## 2. `ft.fun` 自定义前向与反向（`function.py`）

当用户需要为复合算子指定数值更稳定的手写梯度公式，或者需要给不透明的自定义 Triton 前向算子配上反向实现时，通过继承 `ft.fun` 定义：

```python
class ScaleAndSquare(ft.fun):
    @ft.jit
    def forward(self, ctx, x):
        ctx.save_for_backward(x)
        return ft.square(x)

    @ft.jit
    def backward(self, ctx, dy):
        (x,) = ctx.saved_tensors
        return (2 * x * dy,)
```

它在 IR 与编译器内部的运作方式非常干净：

- **强制 `@ft.jit` 与封闭追踪**：`forward` 以及（若提供的）`backward` 都必须带 `@ft.jit`。当外层图调用 `op(x)` 时，不会把 `forward` 摊平打散，而是单独追踪出子函数体存入 `Module.metadata["functions"][callee]`，并在外层插入一条 `fuga.call` 指令。
- **显式 SSA 保存通道**：`ctx.save_for_backward(...)` 保存的中间张量并不是藏在某个脱离编译器的 Python 全局列表里，而是作为 `fuga.call` 额外的 `saved` SSA 输出端口显式流向 `vjp` 阶段！这样死代码消除与跨层缓存都能精确感知它们的依赖。
- **求导展开与手写 Triton 反向**：在 `vjp` 阶段，编译器追踪用户的 `backward(ctx, dy)`（支持单输出或 tuple 多输出余切，并严格校验返回的梯度 tuple 长度、各浮点输入的 shape/dtype 一致性）。用户在 `backward` 里同样可以直接调用 [`ft.triton.kernel`](04-ASK桥接与多后端执行.md#cuda-and-triton) 编写的 GPU 反向算子；得益于引擎层的无用物理端口裁剪，像“只依赖 `dy` 而不读取正向 `x`”的单输入 Triton 反向 kernel 也能无缝通过单端口融合契约！

<a id="higher-order"></a>

## 3. 基于 JVP / VJP 闭合的高阶自动微分

为什么开启 `y.backward(create_graph=True)` 后，拿到的 `dx = x.grad` 还能继续调用 `dx.backward()` 求二阶、三阶导数？

秘诀在于 **Fuga IR 原语集的闭合性**：

- 基础算子 `constant`、`splat`、`add`、`mul`、`cast` 的前向微分规则（`jvp`）和反向伴随规则（`vjp`）产出的结果，**全部还是这五种基础算子本身**（例如乘法的 `vjp` 产出两条 `fuga.mul`，累加余切产出 `fuga.add`，`f16 ↔ f32` 类型转换的 `vjp` 产出反向 `fuga.cast`）。
- 当 `create_graph=True` 时，每一段反向 VJP 模块不再直接裸调底层 executable，而是包装成一次正常的 `@ft.jit` 计算执行——因此反向算出的 `x.grad` 自身也挂上了完整记录“反向计算图”的新 `GradHistory`！
- 对 `x.grad` 再次调用 `.backward()`（记得先 `x.zero_grad()` 以免把一阶和二阶梯度混加在一起），无非是对上一轮产出的那张 Fuga IR 反向图再做一次完全相同的 `vjp` 变换并交给 ASK 编译执行。只要全链路都由基础算子或纯 Fuga 运算组成的 `ft.fun` 构成，任意阶求导都能自然闭合。

<a id="preflight-validation"></a>

## 4. 零半成品污染的反向预检（Preflight Validation）

遇到没有注册 `ft.fun.backward` 的裸 `fuga.external`（不透明 Triton 算子），或者对包含不透明 Triton 正向/反向的 `ft.fun` 请求二阶及以上高阶导数（`create_graph=True` 后再对依赖不透明节点的梯度求导）时，框架必须拒绝，而且**绝不能跑到一半写脏了一部分叶子的 `.grad` 后才抛异常**。

`autograd.py` 在真正执行任何一段反向代码之前，会先对整张反向拓扑图做一次完整的**只读预检**：

1. 结合 C++ [`analyze_function`](02-原生图分析与C++边界.md#native-analyze) 给出的 `reverse_ops`，精确识别真正在当前求导路径上的每一个算子（旁路未使用的 `fuga.external` 自动豁免）；
2. 试运行每一段待执行的 `vjp` 图构建；若发现裸 `fuga.external` 缺少反向规则，或 `create_graph=True` 产出的梯度图里混入了无法继续做 JVP/VJP 分解的不透明外部算子，当场记录不可微原因或直接抛出清晰的 `TypeError` / `ValueError`；
3. 只有全部节点的反向 IR 都合法生成并通过校验后，才开始编译执行并更新叶子 `.grad`，保证失败时用户状态 100% 干净。
