# 03. 自动微分与自定义算子

前端通过 `requires_grad=True`、`y.backward()` 与 `x.grad` 驱动自动微分；每一段反向计算均通过 Fuga IR 的 `vjp` 变换生成静态反向图，再交由 ASK 编译为原生 CPU 或 GPU 代码执行。

<a id="runtime-autograd"></a>

## 1. 运行时 `GradHistory` 与反向调度（`autograd.py`）

梯度历史在待计算 Tensor 创建时记录，与何时读取结果无关。`ft.no_grad()` 包围的表达式不挂载历史；离开该上下文后再读取结果不会补挂历史。

1. **挂载历史节点**：若相关输入含 `requires_grad=True` 的浮点张量，`_Node` 保存原始 Fuga IR、输入 Tensor、输出身份与类型、需要梯度的输入端口。输出通过节点与输出索引连接上游历史；数值执行不会替换这些稳定的 Tensor 句柄。
2. **检查梯度种子**：0-D 输出省略种子时使用同设备、同类型的标量 `1.0`；非标量必须提供同形状、同类型、同 Engine 的种子。错误种子与不可求导路径在执行前拒绝。
3. **逆拓扑回传与叶子累加**：对收到余切的输出用 [`project_outputs`](02-原生图分析与C++边界.md#transforms-reuse) 裁剪无关分支，构造各节点的 [`vjp`](../ir/02-控制流与可组合变换.md#jvp-and-vjp) 计划。预检全部通过后，将反向表达式和累加表达式合并执行，成功后再统一更新叶子 `.grad`。
4. **图生命周期**：默认一次 `backward()` 完成后释放历史，重复反向会报错；`retain_graph=True` 或默认随 `create_graph=True` 保留历史时可继续使用。`detach()` 保留数值依赖、断开梯度连接，本身不要求立即执行；`zero_grad()` 清空 `.grad`。

实际依赖范围由 C++ 图分析确定。普通 Python 标量条件前后的图通过 Tensor 输入连接，反向沿此次实际计算路径传播。

## 2. `ft.fun` 自定义前向与反向（`function.py`）

需要自定义梯度公式或为外部 Triton 算子提供反向实现时，继承 `ft.fun`：

```python
class ScaleAndSquare(ft.fun):
    def forward(self, ctx, x):
        ctx.save_for_backward(x)
        return ft.square(x)

    def backward(self, ctx, dy):
        (x,) = ctx.saved_tensors
        return (2 * x * dy,)
```

- **封闭追踪与 `fuga.call`**：类中直接定义普通方法。调用 `op(x)` 时自动隔离追踪 `forward`，将其子模块与定义校验器保存到 `CallSpec`，并在外层插入 `fuga.call` 指令。方法签名、保存值类型、实例的不可变配置及方法定义身份均被校验；构图后修改这些实例属性或替换方法会使旧图报错，不能静默复用旧求导规则。
- **Python 状态边界**：求导配置应放在实例的不可变属性中；运行时 Tensor 通过显式参数传入，需要留给反向的值用 `ctx.save_for_backward(...)` 保存。普通闭包与全局变量中的可变内容不在自动定义检查范围内。修改这些捕获内容后，须调用 `op.clear_cache()` 使旧图失效，再重新构图；它不会替旧图冻结任意 Python 对象。
- **SSA 保存通道**：`ctx.save_for_backward(...)` 保存的中间张量作为 `fuga.call` 额外的 `saved` SSA 输出端口显式传给 `vjp` 阶段，使死代码消除和缓存能感知其依赖。
- **反向展开**：`vjp` 阶段追踪 `backward(ctx, dy)`（支持单输出或 tuple 多输出余切，并校验返回的梯度 tuple 长度及各浮点输入的 shape/dtype）。`backward` 中同样可以调用 [`ft.triton.kernel`](04-ASK桥接与多后端执行.md#cuda-and-triton) 注册的 GPU 反向算子；引擎层会裁剪未使用的物理输入端口，避免把未用的签名参数带入编译；外部算子由 ASK 执行计划作为独立步骤调度。

<a id="higher-order"></a>

## 3. 基于 JVP / VJP 闭合的高阶自动微分

基础算子 `constant`、`splat`、`add`、`mul`、`cast` 的前向微分规则（`jvp`）和反向伴随规则（`vjp`）产出的指令仍全部属于这五种基础算子（例如乘法的 `vjp` 生成两条 `fuga.mul`，余切累加生成 `fuga.add`，可微浮点间的 `cast` 生成反向 `fuga.cast`）。

开启 `y.backward(create_graph=True)` 时，VJP 计算继续构建可微表达式，算出的 `x.grad` 保留反向图的梯度历史。先保存 `first = x.grad`，再调用 `x.zero_grad()` 与 `first.backward()`，即可继续对该图应用 `vjp` 并交由 ASK 执行，计算二阶、三阶导数。

<a id="preflight-validation"></a>

## 4. 反向预检（Preflight Validation）

遇到未提供 `ft.fun.backward` 的裸 `fuga.external`，或对包含不透明 Triton 正向/反向的 `ft.fun` 请求二阶及以上导数时，必须在启动反向执行和改写任何叶子 `.grad` 之前拒绝。

`autograd.py` 在编译执行任何反向节点前，先对整张反向拓扑图执行一轮只读预检：

1. 根据 C++ [`analyze_function`](02-原生图分析与C++边界.md#native-analyze) 返回的 `reverse_ops` 定位实际处于当前求导路径上的算子（未连接到目标输出的旁路 `fuga.external` 不受影响）；
2. 预先构建各节点的 `vjp` 模块；若裸 `fuga.external` 缺少反向规则，或 `create_graph=True` 产出的梯度图依赖无原语规则的不透明外部算子，直接抛出 `TypeError` / `ValueError`；
3. 全部节点的反向 IR 通过构建与校验后，才开始编译执行并更新叶子 `.grad`。
