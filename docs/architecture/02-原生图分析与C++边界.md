# 02. 原生图分析与 C++ 边界

返回架构总览：[独立 Fuga IR 与 C++ 原生图分析](README.md#arch-ir-native) · 相关细节：[张量模型与追踪机制](01-张量模型与追踪机制.md) · [自动微分与自定义算子](03-自动微分与自定义算子.md) · [Fuga IR 对象模型](../ir/01-对象模型与验证.md)

随着自动微分（尤其是多输出部分求导、带副作用算子剪枝与高阶导数嵌套）的引入，编译器需要频繁在 Fuga IR 上回答“哪些节点受可微输入影响”、“哪些节点真正在通往目标输出的路径上”、“哪些不透明算子挡在必经反向路径上”。FugaTensor 将这部分密集的 SSA 图拓扑分析实现在必选的 C++17 `nanobind` 扩展 `fugatensor._native` 中。

<a id="python-cpp-boundary"></a>

## 1. Python 与 C++ 的现实职责边界

在工程文档里我们实话实说，只记录当前真正落地的边界：

| 层级 | 代码位置 | 当前承担的职责 |
| --- | --- | --- |
| **Python 框架与 IR 层** | `src/fugatensor/*.py`、`src/fugatensor/ir/*.py` | 用户态 `Tensor` / `@ft.jit` / `ft.fun` / `ft.triton` API、Python 追踪与 Graph Break 调度、Fuga IR 对象结构、JVP/VJP 求导规则展开、向 ASK IR 降级以及 `Engine` 后端编排。 |
| **FugaTensor 原生 C++ 扩展** | `cpp/graph.h`、`cpp/graph.cpp`、`cpp/bindings.cpp`（编译为 `fugatensor._native`） | 扁平化 SSA 图契约严格校验、前向微分可达性分析、带副作用保活的逆向死代码分析、微分子图活跃性交集计算与逆拓扑反向求导调度表生成。 |
| **ASK 原生 C++ 编译与运行时** | 同级 `ask` 仓库（`ask._native` / `ask-opt`） | `ask` dialect 校验与优化、CPU / 自有 CUDA 原生 LLVM IR 代码生成、跨编译器值边界内联、CUDA Driver 常驻会话与双层持久缓存。 |

`fugatensor._native` 是构建与导入 FugaTensor 时的**必选组件**（`ir/transforms.py` 直接 `from .. import _native`，不存在隐藏的纯 Python 慢速回退分支），确保线上与测试始终走同一套经过严格类型校验的 C++ 分析逻辑。

## 2. 三向可达性与反向边界分析（`cpp/graph.cpp`）

`fugatensor._native.analyze(...)` 接收一张 Fuga `Function` 的紧凑整数编码快照：`num_values`、按拓扑序排列的 `op_operands` / `op_results` / `op_has_effects`、`outputs` 以及需要求导的输入值集合 `selected_inputs`。

C++ 核心首先对输入做零妥协的契约检查（拒绝任何负数或越界 Value ID、重复结果定义、非拓扑序的前向悬空引用；在 `bindings.cpp` 中还显式拦截用 Python `bool` 冒充整数 ID 的静默类型转换），随后在 $O(V + E)$ 时间内完成四步不动点与图扫描：

1. **前向种子传播（`forward_from_selected`）**：从 `selected_inputs` 出发沿 `operand → result` 正向标记所有直接或间接依赖自变量的值。若某个算子完全不依赖自变量（例如只由常量或非求导整数索引算出的系数），它就不需要反向规则。
2. **输出数据流逆向可达（`reaches_selected_outputs`）**：仅从函数声明的 `outputs` 出发沿 `result → operand` 逆向回溯。
3. **带副作用保活的通用活跃集（`live_values` / `live_ops`）**：在 `outputs` 之外，将 `op_has_effects == true` 的算子也作为保活根逆向标记其操作数依赖，使得死代码消除（DCE）不会误删有外部副作用的节点。
4. **微分子图交集与逆拓扑边界（`active_ops` / `reverse_ops`）**：
   - 一个值只有在**既受 `selected_inputs` 正向影响，又能沿纯数据流到达 `outputs`** 时，才属于微分子图（`active_values = forward ∩ reaches_outputs`）。
   - 这条规则非常关键：哪怕图里有一个未使用的外部算子或悬空副作用节点，只要它没有流向最终要求导的 `outputs`，或者它的输入根本不依赖求导自变量，它就不会进入 `reverse_ops`（即不会无辜触发“缺少反向规则”报错，同时在保留副作用时仍留在 `live_ops` 中）。
   - 多返回值算子（如返回多个张量或携带 `saved` 状态的 `fuga.call`）作为一个整体原子边界在 `reverse_ops` 中按严格逆拓扑序只出现一次，杜绝汇聚路径重复求导。

<a id="transforms-reuse"></a>

## 3. 统一图变换基础设施（`ir/transforms.py`）

为了避免求导器、高阶 JVP、运行时反向缓存和执行引擎各自手写一套图裁剪逻辑，`ir/transforms.py` 在 `_native.analyze` 之上封装了三个全仓复用的纯函数：

- **`analyze_function(function, selected_inputs)`**：把含嵌套 `Region` 的 Fuga `Function`（自动提取 `if`/`for`/`while` 子区域捕获的自由外部 SSA 值作为该控制流算子的有效操作数）编码给 `_native.analyze`，返回强类型的 `NativeGraphAnalysis`。
- **`prune(module)`**：传入空的 `selected_inputs=()` 调用 `analyze_function`，按 `live_ops` 重建剔除死代码并递归清理子区域后的干净 `Module`，同时完整保留函数级与模块级 `metadata`（如外部 Triton 实现表 `external_implementations` 与内联子函数字典 `functions`）。
- **`project_outputs(module, output_indices)`**：在不改动正向语义的前提下把 `Function.outputs` 投影到真正在反向中需要梯度种子的输出子集上，再调用 `prune(module)` 把与目标输出无关的旁路分支连根剪除。

这套组合在 `ir/differentiate.py`、`ir/jvp.py`、`autograd.py` 与 [`engine.py` 的无用物理输入端口裁剪](04-ASK桥接与多后端执行.md#engine-lifecycle) 中共享，保证了全链路活跃性判定的一致性。

<a id="gil-and-concurrency"></a>

## 4. 无状态设计与多线程 GIL 释放

`cpp/graph.cpp` 中的 `analyze_graph(const GraphInput&)` 完全使用栈上局部变量与只读输入引用，**没有任何静态缓存、单例状态或跨请求共享容器**。

在 `cpp/bindings.cpp` 中，完成 Python 序列到 C++ `GraphInput` 的参数拷贝与类型校验后，立即通过 `nb::gil_scoped_release` 释放 Python GIL 执行原生图分析，分析完毕后再重新获取 GIL 构造只读的 `AnalysisResult` 返回。多线程并发追踪或并行求导请求之间天然隔离、互不阻塞（由 `tests/test_native_graph.py` 中的多线程并发一致性测试持续守护）。
