## 1. `Tensor` 存储与待计算状态（`tensor.py` / `ops.py`）

`ft.tensor(data, *, dtype=ft.fp32, engine=None, device=None)` 从规则嵌套数据推断形状，负责矩形校验与字节编解码；按尺寸创建使用 [`zeros`、`ones`、`empty`、`full`](../API/张量与数据交换.md#size-factories)。CPU 的 bool、i32、i64、f32、f16 输入使用紧凑的 `ctypes` 缓冲区；CUDA 另支持 bf16，输入直接编码为字节并上传到 [ASK `ExecutionSession`](../../../ask/docs/常驻运行时与多级缓存.md#execution-session) 管理的设备存储。六个类型对象对应 [ASK 的 6 种基础类型](../../../ask/docs/ASK-IR与数值语义.md#types-and-precision)；浮点表达式可通过 `ft.grad` 对指定输入求导。

张量运算先返回待计算的 Tensor，记录形状、类型、Engine 和输入依赖。例如 `y = (x + 1).square()` 会记录加法和平方，减法、取负和平方由加乘基础算子组合。

Tensor、TraceTensor 和 Triton 的 TensorSpec 返回 `DType` 单例与设备对象，内部 IR 和后端存储使用 `f32`、`f16` 等编码。框架按设备复用默认 Engine。

[`reshape`](../API/张量与数据交换.md#reshape) 生成延迟执行的 `fuga.reshape`，保留输入依赖和表达式来源。降级后的 `ask.reshape` 和外部 kernel 元信息都使用目标形状。JVP 将切线改为输出形状，VJP 将余切恢复为输入形状。输出存储由执行计划分配，接口不保证与输入共享存储。

`shape`、`dtype`、`device` 与 `repr` 只读取元信息。`.tolist()`、`.storage` 与 0-D 标量真值读取会触发计算；CUDA `.tolist()` 还会等待并下载结果。`ft.evaluate(y)` 返回原 Tensor；`ft.evaluate(a, b)` 可合并共享依赖，一起提交多个输出。

<a id="buffer-io"></a>

已有连续内存时，使用 `ft.from_buffer(data, dtype=..., shape=..., device=None, copy=True)` 或 `engine.from_buffer(...)` 批量导入，避免逐元素转成 Python 数值。输入须实现 buffer protocol 且按 C 顺序连续；带元素类型的 buffer 必须匹配 dtype、元素宽度及本机字节序，`bytes`、`bytearray` 和字节视图按显式 dtype 解释原始位模式。字节数必须与 shape 一致；原始字节导入保留 NaN payload 和负零，bf16 张量选择 CUDA。通用 buffer 格式校验位于 `_buffers.py`；CPU 创建或借用 `HostStorage`，CUDA 校验后直接上传到设备存储。

```python
from array import array
import fugatensor as ft

source = array("f", [1.0, 2.0, 3.0])
x = ft.from_buffer(source, shape=(3,), dtype=ft.fp32, device="cpu")
raw = (x + 1).to_buffer()  # 只读 memoryview，内容为连续原始字节
```

默认导入和导出均复制数据。CPU `from_buffer(..., copy=False)` 借用可写且对齐的存储并保活原对象；原对象后续写入会改变 Tensor 内容，调用方须自行避免与执行并发修改。CPU `.to_buffer(copy=False)` 返回保活存储的只读视图，只读限制针对该视图，不能阻止其他所有者修改同一内存。CUDA 导入和导出需要主机与设备间传输，只接受 `copy=True`；`.to_buffer()` 会先完成待计算图并等待下载。

## 2. 自动合图与引擎缓存（`_lazy.py` / `engine.py`）

普通 Python 函数每次调用正常执行。函数调用边界不触发张量执行，跨函数产生的表达式仍可合并：

```python
def shift(x):
    return x + 1

def scale(x):
    return shift(x) * 2

y = scale(x)       # 记录 add 和 mul
ft.evaluate(y)     # 合并依赖图后 JIT 编译执行
```

内部追踪结束后，表达式图冻结为不可变模板，缓存按输出选择得到的数值投影。表达式来源保留自定义求导的 `fuga.call` 边界；数值投影展开子函数并裁剪未使用的输入。

自定义函数和外部算子回调每次调用时执行。相同追踪结果复用模板，配置或函数定义变化则形成新模板。

执行时从输出回溯到已有存储的输入，以模板投影、表达式连接、共享叶子、输出顺序和相关定义身份组成结构键。键包含输入形状、类型和图中常量，运行时元素值和内存地址留到执行时绑定。缓存未命中时拼接 Fuga IR、保存文本并编译；命中时绑定本次输入直接执行。每次调用校验活跃图中的函数定义。

执行成功后，结果存回请求的 Tensor，表达式来源保持连接，后续 `ft.grad` 仍可追溯求导。后续读取复用结果；中间 Tensor 按需保存存储。缓存和诊断接口见 [ASK 桥接与多后端执行](ASK桥接与多后端执行.md#cache-hierarchy)。

## 3. 内部追踪与自定义函数隔离（`_jit.py` / `tracing.py`）

内置算子与 `ft.fun` 使用 `TraceContext` / `TraceTensor` 构造 Fuga IR。自定义函数的 `forward(self, ...)` 追踪为前向子函数；可选 `vjp(self, primals, outputs, cotangents)` 在求导时构造余切表达式，普通前向则使用原语微分规则。

追踪 Tensor 的 `detach()` 与 `ft.stop_gradient(...)` 生成 `fuga.stop_gradient`，可在前向和 VJP 中冻结局部微分依赖；数值仍由原表达式提供。运行时 `ft.grad` 在隔离追踪之外调用。

追踪时，`.shape`、`.dtype` 与 `.device` 是可供 Python 分支读取的静态元信息。`x + 2.5` 按 `x.dtype` 生成常量，再用 `fuga.splat` 填成 `x.shape`。两个 Tensor 的二元运算要求形状、类型和设备相同。

自定义函数不能捕获外部真实 Tensor 混入追踪，不能在方法中读取张量数据或创建真实 Tensor。运行时张量状态须作为显式输入传入。纯 VJP 参数、方法签名与定义变更检查见 [自定义函数](自动微分与自定义算子.md#custom-fun)。

## 4. Python 标量条件形成执行边界

普通 Python 的 `if cond:` 或 `while cond:` 要求条件 Tensor 为 0-D，否则报错。读取条件时执行其依赖图，再由 Python 选择分支或继续循环；其他表达式保持待计算状态。

分支和循环每次根据实际数据执行，梯度沿本次形成的图传播。条件读取前后的表达式通过 Tensor 的表达式来源连接。

`ft.fun` 的 `forward` / `vjp` 会追踪为子函数，只能用静态元信息决定分支。依赖张量数值的控制流应放在外层 Python 代码中。
