## 1. `Tensor` 存储与待计算状态（`tensor.py` / `ops.py`）

`ft.tensor(data, dtype="f32", shape=None, device=None, requires_grad=False)` 负责矩形数据校验与字节编解码。CPU 输入使用紧凑的 `ctypes` 缓冲区；CUDA 输入上传到 [ASK `ExecutionSession`](../../../ask/docs/05-常驻运行时与多级缓存.md#execution-session) 管理的设备存储。支持 [ASK 的 6 种基础类型](../../../ask/docs/01-ASK-IR与数值语义.md#types-and-precision)，`fp16` 规范化为 `f16`；只有 `f16`、`bf16`、`f32` 可设置 `requires_grad=True`。

张量运算先返回待计算的 Tensor，记录形状、类型、所属 Engine 与输入依赖。例如 `y = (x + 1).square()` 此时只组图，减法、取负和平方在图中展开为加乘基础算子。用户可直接写表达式或普通 Python 函数，无需装饰器。

`shape`、`dtype`、`device` 与 `repr` 仅读取元信息。`.tolist()`、`.storage`、0-D 标量真值读取和 `.backward()` 会触发所需计算；CUDA `.tolist()` 还会等待结果并下载到主机。显式 `ft.evaluate(y)` 返回原 Tensor；`ft.evaluate(a, b)` 可一起提交多个输出，让共享依赖参与同一次图合并。张量元素算术始终由 ASK 编译执行。

## 2. 自动合图与引擎缓存（`_lazy.py` / `engine.py`）

普通 Python 函数每次调用正常执行。函数调用边界不触发张量执行，跨函数产生的表达式仍可合并：

```python
def shift(x):
    return x + 1

def scale(x):
    return shift(x) * 2

y = scale(x)       # 记录 add 和 mul
ft.evaluate(y)     # 合并依赖图后 JIT 编译执行
```

执行时从所需输出回溯到已有存储的输入，裁剪无关依赖并按拓扑序拼接待计算表达式。原始表达式和梯度历史保留自定义求导的 `fuga.call` 边界；数值求值使用展开后的副本，以识别子函数未使用的输入。引擎按合并后的 Fuga IR 文本和相关 `ft.fun` 定义身份缓存可执行代码；输入类型和图中常量参与键，运行时输入元素值不参与键。缓存命中跳过编译，用户 Python 逻辑仍按次运行。

成功执行后给所请求的 Tensor 填入存储并保留其原有梯度历史，后续读取同一结果不重复执行。没有请求的中间 Tensor 不保证保存独立存储。`engine.cache_info()`、`engine.clear_cache()` 与 `engine.last_fuga_ir` 等诊断接口见 [ASK 桥接与多后端执行](04-ASK桥接与多后端执行.md#cache-hierarchy)。

## 3. 内部追踪与自定义函数隔离（`_jit.py` / `tracing.py`）

内置算子与 `ft.fun` 在内部使用 `TraceContext` / `TraceTensor` 构造 Fuga IR。它们是实现机制，用户函数不需要声明 JIT 装饰器。自定义函数的普通 `forward(self, ctx, ...)` 与可选 `backward(self, ctx, dy)` 会自动建立稳定的内部包装，并单独追踪为可求导的子函数。

隔离追踪中，`.shape`、`.dtype` 与 `.device` 是静态元信息，可以用于 Python 分支；`x + 2.5` 的 Python 常量按 `x.dtype` 生成 `fuga.constant`，必要时用 `fuga.splat` 填成 `x.shape`。两个 Tensor 的二元运算要求同形状、同类型，不做隐式广播或类型提升。

自定义函数不能捕获外部真实 Tensor 混入追踪，不能在方法中读取张量数据、创建真实 Tensor 或切换 `no_grad`。运行时张量状态须作为显式输入传入。保存值通道、方法签名与定义变更检查见 [自定义函数](03-自动微分与自定义算子.md#custom-fun)。

## 4. Python 标量条件形成执行边界

普通 Python 的 `if cond:` 或 `while cond:` 每次读取 Tensor 真值时，先检查其形状：非 0-D Tensor 直接报错，不做隐式 `any()` / `all()`；0-D Tensor 则执行条件所依赖的待计算图，读取标量真值，再由 Python 选择分支或继续循环。其它尚未被读取的表达式可以继续保持待计算状态。

分支和循环每次遵循实际数据，梯度沿此次形成的图传播；不会把第一次调用的分支选择固定到编译缓存。条件读取前后的表达式通过 Tensor 依赖及梯度历史连接。

`ft.fun` 的 `forward` / `backward` 必须提取为完整的隔离子函数，不支持在其中读取 `TraceTensor` 真值来选择数据依赖分支。这类控制流应放在外层普通 Python 代码中。
