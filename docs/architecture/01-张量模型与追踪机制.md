## 1. `Tensor` 存储模型（`tensor.py` / `ops.py`）

`ft.tensor(data, dtype="f32", shape=None, device=None, requires_grad=False)` 负责矩形数据校验与字节编解码，不执行张量元素算术：

- **类型与底层存储**：支持与 [ASK 6 种基础类型](../../../ask/docs/01-ASK-IR与数值语义.md#types-and-precision) 对应的 `bool`、`i32`、`i64`、`f32`、`f16`、`bf16`（`fp16` 规范化为 `f16`）；仅浮点类型（`FLOAT_DTYPES = {"f16", "bf16", "f32"}`）可设置 `requires_grad=True`。
  - **CPU 存储（`HostStorage`）**：分配紧凑的 `ctypes` 字节缓冲区，复用 ASK 的单步 RNE 编解码函数将 `f16`/`bf16` 存为 16 位二进制值。
  - **CUDA 存储（`DeviceTensor`）**：持有 [ASK 常驻 `ExecutionSession`](../../../ask/docs/05-常驻运行时与多级缓存.md#execution-session) 上的设备张量句柄；创建时上传数据，`repr()` 仅读取形状、类型和设备元信息，`.tolist()` 时同步流事件并拷回主机。
- **内置算子统一走 `@ft.jit`**：`ops.py` 中的 `ft.add`、`ft.multiply`、`ft.subtract`、`ft.negative`、`ft.square`、`ft.cast`、`ft.zeros_like` 与 `ft.ones_like` 均声明为 `@ft.jit` 函数；其中减法（`a + b * -1`）、取负（`x * -1`）和平方（`x * x`）由加乘基础算子组合展开。直接调用 `(x - y).square()` 与编写自定义 `@ft.jit` 函数走相同的追踪和编译路径。

<a id="jit-specialization"></a>

## 2. `@ft.jit` 特化键与嵌套内联（`jit.py`）

调用 `@ft.jit` 函数时，调度器根据实参构造特化键（Specialization Key）：

1. **所属 `Engine`**：按 `weakref` 分桶隔离不同设备或不同工具链配置的编译产物，`Engine.close()` 时清理对应条目。
2. **输入参数签名**：对 `Tensor` 参数提取 `(shape, dtype)`（不包含张量数据、`requires_grad` 或内存地址）；对静态 Python 参数（`bool`、`int`、`float`、`str`、`None`）按类型与值特化（区分 `+0.0` 与 `-0.0`，归并 `NaN`）。
3. **`ft.fun` 定义版本**：计算体内引用自定义 `ft.fun` 实例时，键中记录该实例标识与定义版本号，区分前向 IR 相同但 `backward` 闭包不同的自定义算子。

当正在被追踪的 `@ft.jit` 函数调用另一个普通 `@ft.jit` 函数时，入参已是 `TraceTensor`，被调函数会直接在当前活跃的 `TraceContext` 中追加 Fuga IR 节点，不会拆成多次独立执行。

<a id="trace-context"></a>

## 3. `TraceContext` 与外部状态边界（`tracing.py`）

冷路径追踪时，`TraceContext` 为每个输入 `Tensor` 创建 `TraceTensor(TensorType(shape, dtype), block_arg_value)`，压入线程局部追踪栈后运行一次 Python 函数：

- **静态属性读取**：`TraceTensor` 的 `.shape`、`.dtype`、`.ndim`、`.numel`、`.device` 为已知静态属性，可直接用于编译期 Python 分支判断（如 `if x.dtype == "f16":`）。
- **外部真实张量隔离**：追踪期间若将闭包捕获的外部真实 `Tensor` 与 `TraceTensor` 混合运算，或调用 `TraceTensor.tolist()`、`ft.tensor(...)`、`with ft.no_grad():`，追踪器直接报错；参与计算的运行时张量均须通过函数参数传入，防止把首次运行的数据固化为图内常量。
- **Python 标量 Splat**：`x + 2.5` 中的标量字面量按 `x.dtype` 生成 0-D `fuga.constant`，并在 `x.ndim > 0` 时补一条 `fuga.splat` 对齐到 `x.shape`；两个张量的二元运算要求同 shape、同 dtype。

<a id="graph-break"></a>

## 4. 0-D 标量条件与图中断（Graph Break）

普通 `@ft.jit` 函数中对 `TraceTensor` 执行 Python `if` 或 `while` 判断时：

- **非标量张量（`ndim > 0`）**：直接报错拒绝，不做隐式 `any()` / `all()` 归约。
- **0-D 标量张量（`ndim == 0`）**：`TraceTensor.__bool__` 触发 Graph Break，在同一 Python 栈帧内分段追踪与执行：
  1. **执行前缀子图**：收集当前 `TraceContext` 中仍被栈帧引用的活跃 `TraceTensor`（通过弱引用表定位）与该条件标量作为前缀子图输出，编译并交由当前 `Engine` 执行（已编译过的前缀直接命中片段缓存 `_segment_cache`）。
  2. **读取标量真值**：从前缀输出中下载该 0-D 条件张量的布尔值。
  3. **原地重绑定并续接追踪**：将刚算出的真实中间 `Tensor`（保留各自的 [`GradHistory`](03-自动微分与自定义算子.md#runtime-autograd)）作为新一段 `TraceContext` 的输入参数，把存活的 `TraceTensor` 原地重绑定到新片段的入口 SSA 值上，随后 Python `if` 或 `while` 进入实际分支继续执行。

这样前缀计算不会重复运行，`while` 循环每一轮可复用同一份已编译的片段代码（通过 `fn.last_segments` 可查看本次执行各段的 `fuga_ir`、`ask_ir` 与报告），且调用 `.backward()` 时梯度沿本次实际走过的分支和循环次数回传。

`ft.fun` 的 `forward` 和 `backward` 需要提取为完整封闭的 `fuga.call` 子函数供求导分析，内部不支持对 0-D `TraceTensor` 触发运行时 Graph Break；动态 Python 控制流应写在外层 `@ft.jit` 函数中。
