# 01. 张量模型与追踪机制

本章顺着用户写下 `ft.tensor(...)` 和 `@ft.jit` 后的第一阶段，讲清楚张量在内存里存了什么、为什么普通 `x + y` 也走 JIT、特化缓存怎么设计，以及遇到依赖运行时数据的 Python `if`/`while` 时怎么优雅切分计算图。

<a id="tensor-model"></a>

## 1. `Tensor` 存储模型与零算术原则（`tensor.py` / `ops.py`）

`ft.tensor(data, dtype="f32", shape=None, device=None, requires_grad=False)` 只做**矩形形状校验与字节编解码搬运**，绝不在 Python 层实现一套“Eager 算术回退”：

- **显式类型与真实位宽存储**：支持与 [ASK 6 种基础类型](../../../ask/docs/01-ASK-IR与数值语义.md#types-and-precision) 一一对应的 `bool`、`i32`、`i64`、`f32`、`f16`、`bf16`（`fp16` 规范化为 `f16`）；只有浮点类型（`FLOAT_DTYPES = {"f16", "bf16", "f32"}`）允许开启 `requires_grad=True`。
  - **CPU 存储（`HostStorage`）**：分配紧凑的 `ctypes` 字节缓冲区，直接复用 ASK 的单步 RNE 编解码规则将 `f16`/`bf16` 存为真实的 16 位二进制字，而不是拿 Python `float` 列表冒充低精度张量。
  - **CUDA 存储（`DeviceTensor`）**：直接持有 [ASK 常驻 `ExecutionSession`](../../../ask/docs/05-常驻运行时与多级缓存.md#execution-session) 上的设备张量句柄；创建时异步上传，`repr()` 只打印形状/类型/设备元信息而不触发同步，调用 `.tolist()` 时才等待流事件并拷回主机。
- **内置算子同样是 `@ft.jit` 函数**：`ops.py` 中的 `ft.add`、`ft.multiply`、`ft.subtract`、`ft.negative`、`ft.square`、`ft.cast`、`ft.zeros_like` 与 `ft.ones_like` 全部用 `@ft.jit` 装饰；其中减法（`a + b * -1`）、取负（`x * -1`）、平方（`x * x`）直接组合基础加乘原语展开。因此在交互式命令行里直接写 `(x - y).square()`，走的也是同一条追踪、编译与自动微分流水线。

<a id="jit-specialization"></a>

## 2. `@ft.jit` 特化键与嵌套内联（`jit.py`）

每次用真实参数调用 `@ft.jit` 装饰的函数时，调度器先构造不可变的**特化键（Specialization Key）**：

1. **所属 `Engine` 身份**：按 `weakref` 分桶隔离，避免把不同设备上下文或不同工具链配置的编译产物混用；`Engine.close()` 时自动清理对应缓存桶。
2. **输入参数签名**：对 `Tensor` 参数只提取 `(shape, dtype)`（**不把数据内容、`requires_grad` 或缓冲区地址放入键**，因此更换张量数值或开关梯度都能直接命中已有可执行代码）；对静态 Python 标量参数（`bool`、`int`、`float`、`str`、`None`）按精确类型与值特化（并用 `math.copysign` 区分 `+0.0` 与 `-0.0`，用 `isnan` 归并 `NaN`）。
3. **当前作用域内的 `ft.fun` 定义快照**：若计算体内引用了自定义 `ft.fun` 实例，键中还会纳入该实例的标识与定义版本号，防止两个前向 IR 文本凑巧相同、但 `backward` 闭包不同的自定义算子串用缓存。

**嵌套调用不破图**：当一个正在被追踪的 `@ft.jit` 函数在内部调用另一个 `@ft.jit` 子函数（包括 `x + 1`、`ft.square(x)` 等内置运算）时，发现入参已经是 `TraceTensor`，子函数会直接在当前活跃的 `TraceContext` 里继续追加 Fuga IR 节点，不会切成两次独立内核启动，也不会断开求导依赖。

<a id="trace-context"></a>

## 3. `TraceContext` 与外部张量隔离（`tracing.py`）

冷路径开始追踪时，`TraceContext` 为每个输入 `Tensor` 创建一个 `TraceTensor(TensorType(shape, dtype), block_arg_value)`，通过线程局部栈激活追踪上下文后执行一次 Python 函数：

- **静态元信息自由读取**：`TraceTensor` 的 `.shape`、`.dtype`、`.ndim`、`.numel`、`.device` 都是确定的静态属性，Python 代码可以直接写 `if x.dtype == "f16": x = x.astype("f32")` 做编译期分支选择。
- **拒绝偷渡闭包真实张量**：如果在被追踪函数里直接拿闭包捕获的外部真实 `Tensor` 与 `TraceTensor` 相加，或者在追踪期调用 `TraceTensor.tolist()`、`ft.tensor(...)`、`with ft.no_grad():`，追踪器会立即抛出明确异常——所有参与运算的运行时张量都必须从函数参数显式传入，彻底杜绝“把第一次运行的偶然输入数据悄悄固化成图内常量”的隐患。
- **Python 标量自动 Splat**：`x + 2.5` 中的标量字面量按 `x.dtype` 生成 0-D `fuga.constant`，并在张量维度非零时补一条 `fuga.splat` 对齐到 `x.shape`；两张量二元运算严格要求同 shape、同 dtype（不做隐式广播或隐式类型提升）。

<a id="graph-break"></a>

## 4. 0-D 标量条件与受控图中断（Graph Break）

当用户在普通 `@ft.jit` 函数里写出依赖运行时张量数值的 Python 控制流（如 `if flag:` 或 `while step:`）时，会出现两类截然不同的情况：

- **非标量张量（`ndim > 0`）**：像 Python 原生规则一样直接报错拒绝，绝不隐式猜测 `any()` 或 `all()`。
- **0-D 标量张量（`ndim == 0`）**：`TraceTensor.__bool__` 触发受控的 **Graph Break**，在**同一个 Python 栈帧内**边跑边切分静态片段：
  1. **暂停并冲刷前缀图**：收集当前 `TraceContext` 里所有尚在 Python 栈帧中存活的 `TraceTensor`（通过弱引用表定位活跃中间值）连同该条件标量一起作为前缀子图的输出，立即编译并交给当前 `Engine` 执行（若该前缀片段此前已编译过，则直接命中片段级内存缓存 `_segment_cache`）。
  2. **同步读取单个标量真值**：从执行结果中仅下载这一个 0-D 条件张量的布尔真假（CUDA 上只同步这一个标量）。
  3. **无缝续接后续追踪**：用刚刚算出的真实中间 `Tensor`（完整携带各自的 [`GradHistory`](03-自动微分与自定义算子.md#runtime-autograd)！）作为新一段 `TraceContext` 的输入参数，把刚才存活的 `TraceTensor` 原地重绑定到新片段的入口 SSA 值上，然后让 Python `if` 或 `while` 自然走进真实命中的分支继续往下跑。

这种“**同帧原地重绑定**”的设计带来了三个很实用的工程收益：

1. 不需要重跑函数开头的代码，前缀算过一次就绝不重复执行；
2. `while` 循环跑多少轮完全由运行时数据决定，每一轮循环体都能复用同一份已编译的静态片段机器码，用户可通过 `fn.last_segments` 逐段检查本次实际跑过的 `fuga_ir`、`ask_ir` 与编译报告；
3. 每一段真实执行过的静态片段都通过 `Tensor` 上的 `GradHistory` 首尾相连，调用 `.backward()` 时梯度严格沿着**本次实际走过的分支与循环轮数**反向回传。

> [!NOTE]
> `ft.fun` 的 `forward` 和 `backward` 需要提取为完整封闭的 `fuga.call` 模块供求导变换分析，因此在其内部不允许对 0-D `TraceTensor` 触发运行时 Graph Break（遇到时会在追踪期直接给出诊断）；动态 Python 控制流应写在外层 `@ft.jit` 编排函数中。
