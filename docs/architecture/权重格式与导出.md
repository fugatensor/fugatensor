# 权重格式与导出

返回架构总览：[权重格式与导出](README.md#arch-weights) · 相关细节：[自动微分与自定义算子](自动微分与自定义算子.md) · [Fuga IR 降级到 ASK](../ir/降级到ASK.md)

权重用 PyTree 表示：嵌套容器保存参数结构，Tensor 叶子保存数组。树的键由调用方命名，加载时再选择设备；这样可以跨 CPU/CUDA 会话和进程恢复权重。

API：[权重读写](../API/权重读写.md)

<a id="weight-goals"></a>

## 1. 设计边界

- **参数树**：嵌套 `dict`、`list`、`tuple` 和 Tensor 构成树，加载后保持容器类型和顺序。
- **稠密数组叶子**：保存 `bool`、`i32`、`i64`、`f32`、`f16`、`bf16` 六种类型的数值，恢复后是新的叶子 Tensor。
- **内容寻址**：每个数组以“dtype + shape + 布局 + 数据”的 SHA-256 作为 ID，文件放在 `arrays/<id>.bin`；相同内容只写一份。
- **版本**：`format = "fuga.weights"`、`schema_version = 1`。版本随容器或存储语义变化，参数命名和网络结构变化继续使用同一格式。
- **原子导出**：先在同级临时目录写完文件，再改名为目标目录。
- **数组格式**：little-endian、连续、行主序。保存时读取主机数值，按 ASK 的单步 RNE 规则编码；NaN payload 往返可能规范化为默认 NaN。

<a id="weight-layout"></a>

## 2. 目录与 manifest

```text
checkpoint/
├── manifest.json
└── arrays/
    ├── 3f2a...c1.bin
    └── 8d09...7e.bin
```

`manifest.json` 示例：

```json
{
  "format": "fuga.weights",
  "schema_version": 1,
  "producer": {"name": "fugatensor", "version": "0.1.0"},
  "metadata": {"step": 1200, "run": "demo"},
  "tree": {
    "kind": "dict",
    "items": [
      {"key": "encoder", "value": {
        "kind": "dict",
        "items": [
          {"key": "weight", "value": {"kind": "array", "array": "3f2a...c1"}}
        ]
      }},
      {"key": "blocks", "value": {
        "kind": "list",
        "items": [{"kind": "array", "array": "8d09...7e"}]
      }}
    ]
  },
  "arrays": {
    "3f2a...c1": {
      "file": "arrays/3f2a...c1.bin",
      "dtype": "f16",
      "shape": [768, 768],
      "nbytes": 1179648,
      "sha256": "b92f...0a",
      "layout": "little-endian-contiguous-row-major"
    },
    "8d09...7e": {
      "file": "arrays/8d09...7e.bin",
      "dtype": "f32",
      "shape": [768],
      "nbytes": 3072,
      "sha256": "18cd...7f",
      "layout": "little-endian-contiguous-row-major"
    }
  }
}
```

- `tree` 的节点只有 `dict`、`list`、`tuple`、`array` 四种；`dict` 的 `items` 保留键顺序，加载时键不能重复。
- `array` 节点只引用 `arrays` 中的 ID。数组 ID 由规范 JSON 头加一个 NUL 再加原始数据计算，避免不同 dtype/shape 的相同字节被错误合并。
- `metadata` 是调用方定义的 JSON 对象，数组节点也可附带 `metadata`；加载器只检查其类型。
- `producer` 记录生成工具及版本，供诊断使用。
- 数组的 `nbytes` 必须等于 `prod(shape) * element_width`；`sha256` 是数据文件的摘要，`array` ID 还会覆盖 dtype/shape 布局头。

字段约束见 [`schemas/weights-manifest-v1.schema.json`](../../schemas/weights-manifest-v1.schema.json)。dtype 使用字符串标签，新类型可由加载器扩展。

<a id="weight-api"></a>

## 3. Python API

```python
import fugatensor as ft

weights = {
    "encoder": {"weight": ft.tensor([[1.0, 2.0]])},
    "blocks": [ft.tensor([1.5, 2.5], dtype=ft.fp16)],
    "steps": ft.tensor(1200, dtype=ft.int32),
}

ft.weights.save("checkpoint", weights, metadata={"run": "demo"})
# 等价入口：ft.save_weights("checkpoint", weights, ...)

loaded = ft.weights.load("checkpoint")
print(loaded["blocks"][0].tolist())         # [1.5, 2.5]
print(ft.weights.read_metadata("checkpoint"))  # {'run': 'demo'}
```

- `save(directory, tree, *, metadata=None, overwrite=False)`：目标已存在时默认报错，`overwrite=True` 允许替换。返回目标 `Path`。
- `load(directory, *, engine=None, device=None)`：跟随当前默认设备，也可用 `device` 或 `engine` 按[张量创建规则](../API/张量与数据交换.md#tensor-create)选择资源，两者同时给出时须匹配。浮点权重在后续表达式中通过 `ft.grad` 显式选择求导。
- `read_manifest(directory)` 返回校验后的 manifest 副本，不读取大数组；`read_metadata(directory)` 只返回调用方 metadata。
- `ft.save_weights` / `ft.load_weights` 是对应的顶层入口。

保存会求值待计算的权重并将数据读回主机；加载返回独立数据输入，不恢复保存前的表达式来源。

<a id="weight-validation"></a>

## 4. 校验与安全

加载器在创建任何 Tensor 前完成：

1. JSON 只允许有限数值，重复键、未知 `format`/`schema_version` 直接失败。
2. 树只接受四种节点；数组引用必须存在，`dict` 键不能重复。
3. 数组的 dtype、shape、`nbytes`、布局、摘要格式逐项校验。
4. 文件路径必须是目录内的 POSIX 相对路径，拒绝绝对路径、`..`、反斜杠和符号链接逃逸。
5. 读取时核对文件长度、`sha256` 以及由 dtype/shape/布局和数据重新计算的数组 ID。
6. 全部校验通过后，按树的顺序创建 Tensor。

保存侧同样拒绝循环引用、非 Tensor 叶子、非字符串或空 mapping 键、非 JSON metadata 和整型溢出。

<a id="weight-extensibility"></a>

## 5. 后续重构的兼容性

- 网络层和参数命名变化只改变 `tree` 的键与结构，继续使用 v1。
- 新增 dtype 由加载器扩展，旧加载器拒绝未知类型。
- 顶层和数组节点的 `metadata` 可保存附加信息。加载器忽略未知顶层扩展字段，树和数组仍按既有规则校验。
- 稀疏、分片、压缩或量化存储需要新的 `layout` 或版本。

权重按单目录保存和加载，每次写出完整清单及其引用的数组数据。

<a id="weight-tests"></a>

## 6. 验证

`tests/test_weights.py` 覆盖：

- 六种 dtype、0-D、空张量、嵌套 dict/list/tuple、metadata 往返；
- 相同内容去重、重复导出拒绝与显式覆盖；
- 非 Tensor 叶子、循环引用、非法 metadata 拒绝；
- 篡改 schema 版本/format、路径逃逸、摘要或字节数不一致拒绝；
- 指定 Engine、设备和浮点权重的加载与后续求导；
- `FUGATENSOR_TEST_CUDA=1` 时 GPU Tensor 经主机字节格式往返。

公开 schema、Python API 与文档在同一提交中维护；修改数组字段或树节点语义必须提升 `schema_version` 并保留旧版本读取路径。
