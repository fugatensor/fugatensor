# 05. 权重格式与导出

返回架构总览：[权重格式与导出](README.md#arch-weights) · 相关细节：[自动微分与自定义算子](03-自动微分与自定义算子.md) · [Fuga IR 降级到 ASK](../ir/03-降级到ASK.md)

FugaTensor 还没有固定的模型类或参数命名规范，但权重需要跨 CPU/CUDA 会话、跨进程保存，并且要在后续增加层、改变模块组织、加入新原子算子时继续可用。因此权重格式采用类似 JAX PyTree 的表示：只描述一棵由数组组成的树，不记录模型类名、算子名、执行图或设备信息。架构变化只改变树的键和形状，不改变容器格式。

API：[权重读写](../API/06-权重读写.md)

<a id="weight-goals"></a>

## 1. 设计边界

- **结构来自调用方**：嵌套 `dict`、`list`、`tuple` 和 `Tensor` 构成树；`dict` 表示命名参数，`list`/`tuple` 表示有序结构。加载后保持类型和顺序，不假设 `layer0`、`weight` 等命名。
- **叶子只有稠密数组**：当前保存 `bool`、`i32`、`i64`、`f32`、`f16`、`bf16` 六种基础类型；不保存梯度、计算历史、优化器状态或设备句柄。
- **内容寻址**：每个数组以“dtype + shape + 布局 + 数据”的 SHA-256 作为 ID，文件放在 `arrays/<id>.bin`；相同内容只写一份。
- **显式版本**：`format = "fuga.weights"`、`schema_version = 1`。新增网络层、改变参数命名或加入原子算子不需要升级版本；只有改变容器/存储语义才需要新版本。
- **原子导出**：先在目标目录同级的临时目录写完全部文件，再改名为目标目录；失败不会留下可被误读的半成品。
- **主机端格式**：数组统一为 little-endian、连续、行主序。保存时从当前 Engine 下载并按 ASK 的单步 RNE 浮点边界编码；NaN payload 不属于 ASK 数值契约，往返可能规范化为默认 NaN。加载时由调用方选择 Engine 或使用当前 Engine。

<a id="weight-layout"></a>

## 2. 目录与 manifest

```text
checkpoint/
├── manifest.json
└── arrays/
    ├── 3f2a...c1.bin
    └── 8d09...7e.bin
```

`manifest.json` 示例：

```json
{
  "format": "fuga.weights",
  "schema_version": 1,
  "producer": {"name": "fugatensor", "version": "0.1.0"},
  "metadata": {"step": 1200, "run": "demo"},
  "tree": {
    "kind": "dict",
    "items": [
      {"key": "encoder", "value": {
        "kind": "dict",
        "items": [
          {"key": "weight", "value": {"kind": "array", "array": "3f2a...c1"}}
        ]
      }},
      {"key": "blocks", "value": {
        "kind": "list",
        "items": [{"kind": "array", "array": "8d09...7e"}]
      }}
    ]
  },
  "arrays": {
    "3f2a...c1": {
      "file": "arrays/3f2a...c1.bin",
      "dtype": "f16",
      "shape": [768, 768],
      "nbytes": 1179648,
      "sha256": "b92f...0a",
      "layout": "little-endian-contiguous-row-major"
    },
    "8d09...7e": {
      "file": "arrays/8d09...7e.bin",
      "dtype": "f32",
      "shape": [768],
      "nbytes": 3072,
      "sha256": "18cd...7f",
      "layout": "little-endian-contiguous-row-major"
    }
  }
}
```

- `tree` 的节点只有 `dict`、`list`、`tuple`、`array` 四种；`dict` 的 `items` 保留键顺序，加载时键不能重复。
- `array` 节点只引用 `arrays` 中的 ID。数组 ID 由规范 JSON 头加一个 NUL 再加原始数据计算，避免不同 dtype/shape 的相同字节被错误合并。
- `metadata` 是调用方自由定义的 JSON 对象；每个 `array` 节点也允许一个可选的 `metadata` 对象，供未来量化参数、来源标记等扩展使用。v1 加载器校验其为对象但不解释内容。
- `producer` 只用于诊断，不参与加载语义；读取器不应依赖生产版本。
- 数组的 `nbytes` 必须等于 `prod(shape) * element_width`；`sha256` 是数据文件的摘要，`array` ID 还会覆盖 dtype/shape 布局头。

机器可读约束见 [`schemas/weights-manifest-v1.schema.json`](../../schemas/weights-manifest-v1.schema.json)。schema 对数组 dtype 保留为字符串，新增 dtype 是加载器能力问题，不是容器格式变更。

<a id="weight-api"></a>

## 3. Python API

```python
import fugatensor as ft

weights = {
    "encoder": {"weight": ft.tensor([[1.0, 2.0]])},
    "blocks": [ft.tensor([1.5, 2.5], dtype=ft.fp16)],
    "steps": ft.tensor(1200, dtype=ft.int32),
}

ft.weights.save("checkpoint", weights, metadata={"run": "demo"})
# 等价入口：ft.save_weights("checkpoint", weights, ...)

loaded = ft.weights.load("checkpoint")
print(loaded["blocks"][0].tolist())         # [1.5, 2.5]
print(ft.weights.read_metadata("checkpoint"))  # {'run': 'demo'}
```

- `save(directory, tree, *, metadata=None, overwrite=False)`：默认拒绝已存在的目标；`overwrite=True` 显式替换。返回目标 `Path`。
- `load(directory, *, engine=None, device=None, requires_grad=False)`：默认跟随当前默认设备，初始为 CPU；显式 `device` 或 `engine` 按[张量创建规则](../API/01-张量与数据交换.md#tensor-create)选择资源，二者同时给出时必须匹配。`requires_grad` 只能用于浮点叶子。
- `read_manifest(directory)` 返回校验后的 manifest 副本，不读取大数组；`read_metadata(directory)` 只返回调用方 metadata。
- `ft.save_weights` / `ft.load_weights` 是同一实现的一等入口。

保存会触发待计算权重的求值并下载到主机；恢复的 Tensor 默认不保留梯度历史。需要训练的叶子显式传 `requires_grad=True`。

<a id="weight-validation"></a>

## 4. 校验与安全

加载器在创建任何 Tensor 前完成：

1. JSON 只允许有限数值，重复键、未知 `format`/`schema_version` 直接失败。
2. 树只接受四种节点；数组引用必须存在，`dict` 键不能重复。
3. 数组的 dtype、shape、`nbytes`、布局、摘要格式逐项校验。
4. 文件路径必须是目录内的 POSIX 相对路径，拒绝绝对路径、`..`、反斜杠和符号链接逃逸。
5. 读取时核对文件长度、`sha256` 以及由 dtype/shape/布局和数据重新计算的数组 ID。
6. 全部校验通过后才按树的顺序创建 Tensor；损坏的包不会产生部分可用的结果。

保存侧同样拒绝循环引用、非 Tensor 叶子、非字符串或空 mapping 键、非 JSON metadata 和整型溢出。

<a id="weight-extensibility"></a>

## 5. 后续重构的兼容性

- **改架构**：增加/删除层、改变模块嵌套、重命名参数只改变 `tree` 的键和结构；v1 容器不需要变化。
- **增加原子算子**：算子不会写入权重 manifest；只要其参数仍是基础稠密数组，格式不变。
- **新增 dtype**：数组记录已经是 dtype 标签，新加载器可扩展支持；旧加载器会明确拒绝未知 dtype，而不是误读字节。
- **附加语义**：顶层 `metadata`、数组节点的 `metadata` 以及顶层未知字段是可扩展点；加载器忽略不理解的顶层扩展，但不会改变树或数组的校验规则。
- **真正的新存储语义**：稀疏布局、分片、压缩或量化容器需要新的 `layout`/版本；这类变化不是普通架构重构，不能用 v1 静默承载。

当前不提供多 rank/分片、增量写入、优化器状态树或 safetensors 互操作；这些都可以在保持 v1 树与数组身份规则的前提下作为独立模块增加。

<a id="weight-tests"></a>

## 6. 验证

`tests/test_weights.py` 覆盖：

- 六种 dtype、0-D、空张量、嵌套 dict/list/tuple、metadata 往返；
- 相同内容去重、重复导出拒绝与显式覆盖；
- 非 Tensor 叶子、循环引用、非法 metadata 拒绝；
- 篡改 schema 版本/format、路径逃逸、摘要或字节数不一致拒绝；
- 指定 Engine 和 `requires_grad` 的加载；
- `FUGATENSOR_TEST_CUDA=1` 时 GPU Tensor 经主机字节格式往返。

公开 schema、Python API 与文档在同一提交中维护；修改数组字段或树节点语义必须提升 `schema_version` 并保留旧版本读取路径。
