## 一段表达式是什么

下面直接构造 Fuga 图，不调用 ASK 构图器：

```python
from fugatensor.ir import Module, TensorType

module = Module()
t = TensorType((3,), "f32")
graph = module.graph("calculate", inputs={"x": t, "y": t}, results=[t])
x, y = graph.inputs["x"], graph.inputs["y"]
two = graph.splat(graph.constant(2, dtype="f32"), (3,))
graph.return_(graph.mul(graph.add(x, y), two))

module.verify()
print(module.to_text())
```

加法的结果是一个有类型的 `Value`。乘法的 operands 引用这个 Value，而非打印后的名字或一段文本。因此，变换可以沿 operands 找到定义、检查使用者、插入新计算，并重新连接结果。

| 对象 | 保存的内容 |
|---|---|
| `Module` | 有名字的函数集合 |
| `Function` | 输入与结果签名、函数体 region |
| `Region` | 归属于一个函数或操作的 block |
| `Block` | 参数、有顺序的操作及终结操作 |
| `Operation` | opcode、operands、results、属性、嵌套 regions、效果及来源标识 |
| `Value` | 独立类型、标识、所属 block，以及产生它的操作 |

`ScalarType` 与 `TensorType` 都属于 Fuga。当前 dtype 是 bool、i32、i64、f32、f16、bf16。标量和零维张量是不同类型：标量用于常量、循环索引等；零维张量仍是张量边界的一部分。TensorType 可以保留未知维度，但提交当前 ASK 执行路径之前必须得到具体 shape。

类型中没有 device 字段，add/mul/cast 也不带线程、布局或 GPU 架构。设备选择属于执行上下文与 ASK 降级目标；用户没有按设备显式分支时，相同的逻辑计算使用同一份 Fuga 图。

## 操作不只保存一个名字

常量保存标量值及 dtype；splat 保存目标 shape；cast 保存结果类型。add/mul 要求两个操作数有相同类型，bool 必须先 cast 为数值类型。检查这些约束时只读取图的类型，不读取实际张量数据。

外部调用保存 `ExternalSpec`：compiler ID、源码、入口、参数绑定、特化常量、固定选项、实现支持的目标种类、grid、形状规则和效果。属性与描述会复制并冻结，避免外部字典在构图后被修改，从而悄悄改变已有图。Triton 源码保持原样；具体 GPU 架构在 ASK 降级边界绑定。Fuga IR 不靠分析源码猜算子的计算或导数。

## Region 的输入必须明确

外层值通过 region 操作的 operands 传入，内部 block 参数接住这些值。内部计算只能使用自己的参数和之前定义的值，不能把另一个 block 的 Python Value 对象直接塞进 operands。region 的终结操作显式交还结果。

这个约束使分支输入、循环状态和反向计算所需的值都能从图中找到。仅靠 Python 闭包捕获的隐藏依赖，无法可靠地重写或检查，因此不会作为 region 的输入方式。

## 怎样检查一张图

builder 在创建操作时检查类型和所属图；`module.verify()` 再完整检查已经构造的结构：

- 操作引用的值必须属于可见作用域，且已经定义。
- 操作数量、输入输出类型和属性必须符合该 opcode 的规则。
- 每个 block 必须以正确的 return 或 yield 结束；条件 region 必须交回 bool 标量或零维 bool 张量。
- 函数返回类型、分支返回类型及循环携带状态必须一致。
- 外部描述中的端口、形状规则和效果必须满足当前协议。

后续变换返回新的 Module，保留输入图用于检查。变换完成后再次验证，避免某个 Pass 产生的悬空引用被拖到 ASK 或 LLVM 阶段才报错。

操作的 `id` 标识当前图中的定义，`origin_id` 记录复制前的来源。展开循环时，同一 body 操作会生成多个不同定义，它们必须有不同 id，但保留相同来源。VJP 中复制的正向操作也保留来源；新生成的梯度运算拥有自己的 id，不把复杂梯度关系伪装成唯一的正向来源。
