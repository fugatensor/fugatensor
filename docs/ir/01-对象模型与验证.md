# 01. 对象模型与验证

返回 IR 总览：[结构化对象模型与严格验证](README.md#ir-object-model) · 相关细节：[控制流与可组合变换](02-控制流与可组合变换.md) · [降级到 ASK](03-降级到ASK.md) · [原生图分析与 C++ 边界](../architecture/02-原生图分析与C++边界.md)

本章介绍 `src/fugatensor/ir/` 的核心数据结构、操作指令集以及 `verify_module` 守护的不变量。

<a id="types-and-ssa"></a>

## 1. 类型与 SSA 值（`ir/types.py` / `ir/core.py`）

- **`TensorType(shape, dtype)`**：
  - `dtype` 固定支持 `("bool", "i32", "i64", "f32", "f16", "bf16")` 六种精确类型（`fp16` 在构造入口统一规范化为 `"f16"`），可微浮点子集定义为 `FLOAT_DTYPES = frozenset(("f16", "bf16", "f32"))`。
  - `shape` 为非负整数 tuple：0-D 标量记作 `()`（打印为 `f32`、`i32` 等无维度前缀形式），多维或含零维空张量记作 `(2, 3)`、`(0, 4)`（打印为 `tensor<2x3xf32>`、`tensor<0x4xf32>`）。
  - 所有维度在当前执行链路上均为具体静态整数，不包含设备字段（CPU 与 CUDA 共用同一套 `TensorType`）。
- **SSA `Value`**：
  - 每个 `Value` 拥有唯一的稳定标识符 `value_id`（例如入口参数 `fuga_main.arg0`、算子结果 `op12.res0`）、可读短名（`%arg0`、`%v3_0`）、`TensorType`、所属 `Block`（`owner`）以及定义它的 `producer`（块参数的 `producer` 为 `None`）。
  - 遵循静态单赋值（SSA）原则：每个 `Value` 只被定义一次，后续所有变换和跨层映射都以 `value_id` 作为确定性追踪键。

<a id="ops-and-regions"></a>

## 2. 操作、基本块、区域与模块层次

对象层次自底向上为 `Value` / `Operation` → `Block` → `Region` → `Function` → `Module`：

```text
Module (functions, metadata={"functions": {...}, "external_implementations": {...}})
 └── Function (name, region, inputs, input_types, output_types)
      └── Region (blocks=[entry_block])
           └── Block (arguments, operations)
                └── Operation (op, operands, results, attrs, regions, origin_id)
```

当前 Fuga IR 定义的全部 `Operation.op` 种类如下：

| 类别 | 操作名 | 语义与关键属性 / 区域 |
| --- | --- | --- |
| **常量与广播** | `constant` | 无操作数，产生一个 0-D 标量值，`attrs["value"]` 保存精确 Python 标量（打印时浮点采用十六进制精确字面量 `float.hex()` 避免十进制舍入失真）。 |
| | `splat` | 将 0-D 标量操作数复制填充到 `attrs["shape"]` 指定的目标张量形状。 |
| **基础逐元素** | `add`、`mul` | 接收两个同 shape、同非 `bool` dtype 的张量，产生同类型结果。 |
| | `cast` | 将单个输入张量显式转换为 `attrs["to"]` 目标 `dtype`（保持 shape 不变）。 |
| **函数与外部算子** | `call` | 调用记录在 `Module.metadata["functions"][callee]` 中的封闭子函数（如 [`ft.fun`](../architecture/03-自动微分与自定义算子.md#custom-fun)），结果列表包含公开输出及 `saved_count` 个供反向使用的中间值。 |
| | `external` | 调用第三方编译器算子，`attrs["spec"]` 保存独立快照的 `ExternalSpec`（编译器 ID、源码原文、端口绑定、常量、grid 与副作用列表）。 |
| **结构化控制流** | `if` | 接收 0-D `bool` 条件，携带 `then` 与 `else` 两个单块 `Region`，两分支的 `yield` 结果类型列表必须完全一致。 |
| | `for` | 静态区间计数循环（`attrs` 含 `start`、`stop`、`step`），循环体 `Region` 块参数依次为 `i64` 归纳变量与 `init_args` 携带状态。 |
| | `while` | 携带 `cond` 与 `body` 两个 `Region`：`cond` 以 `condition(flag, *carried)` 终结，`body` 以 `yield(*next_carried)` 终结。 |
| **终结符** | `return`、`yield`、`condition` | 分别作为顶层 `Function`、分支/循环体 `Region` 与 `while` 条件 `Region` 的末尾终结指令。 |

每个 `Operation` 还带有一个 `origin_id`：在克隆、循环展开或微分生成新节点时继承源节点线索，最终写入 [`fuga-to-ask.json`](03-降级到ASK.md#external-and-sourcemap)。

<a id="module-verifier"></a>

## 3. 结构化校验器（`ir/verify.py`）

`verify_module(module)` 不依赖后端编译器，直接在框架层拦截任何非法 IR 构造，失败时抛出带精确位置上下文的 `VerificationError`：

1. **支配与作用域检查**：任意操作数要么是当前（或外层祖先）`Block` 的入口参数，要么是由同一块中排在它前面的指令、或外层祖先块中排在包含该 `Region` 的父指令之前的指令所产生——严禁跨兄弟分支引用或先使用后定义。
2. **块结构与终结符检查**：每个 `Region` 必须包含单个非空 `Block`，终结符（`return` / `yield` / `condition`）只能且必须出现在块末尾，且操作数类型与 `Function.output_types` 或父控制流指令的返回类型逐一匹配。
3. **各算子专属类型契约**：例如 `add`/`mul` 拒绝 `bool` 或异构 shape/dtype、`splat` 要求输入必为 0-D 标量、`if`/`condition` 要求条件必为 0-D `bool`、`for` 要求 `step != 0` 且块参数与初始状态对齐、`call` 校验被调子函数签名一致。
