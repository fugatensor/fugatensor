# 原子算子与可组合变换

[返回 Fuga IR](README.md) · [对象与验证](01-对象模型与验证.md) · [backward 与高阶图](04-JIT与自定义梯度提案.md) · [ASK 边界](03-降到ASK.md) · [ASK 顶层设计](../../../ask/docs/核心思想.md#10-fugatensor-放在哪里)

Fuga 的基础算子把三件事放在同一份可执行规则里：给定输入类型推导结果类型，给定输出梯度生成输入梯度，给定输入切向量生成输出切向量。变换结果仍是 Fuga 操作，下一次变换可以继续处理它，而不是得到无法展开的 Python 计算或机器码。

实现见 [primitives.py](../../src/fugatensor/ir/primitives.py)。`PrimitiveRule` 的主要字段如下：

| 字段 | 调用约定 | 返回什么 |
|---|---|---|
| `abstract_eval` | `(input_types, semantic_attrs)` | 结果类型 tuple |
| `vjp` | `(builder, op, primals, cotangent, active)` | 每个输入的 cotangent 或结构性零 |
| `jvp` | `(builder, op, primals, tangents)` | 每个结果的 tangent 或结构性零 |

这些字段都是实际调用的函数。`PRIMITIVE_RULES` 是只读的内部目录，不是只有名字和说明的允许列表；当前没有公开的运行时原语注册 API，也不依赖 JAX 安装。

## 1. 构图和验证使用相同的抽象求值

抽象求值只读取类型和静态属性，不读取 Tensor 数据。例如 mul 的两侧必须有完全相同的 shape 和 dtype，结果保持该类型：

```python
from fugatensor.ir import TensorType
from fugatensor.ir.primitives import infer_result_types

t = TensorType((3,), "f32")
assert infer_result_types("mul", (t, t)) == (t,)
```

Builder 调用这条规则创建结果，verifier 再用同一规则检查声明的结果。不能在构图时猜一次形状、验证时用另一套规则。constant 和 cast 的目标 dtype 作为语义参数传入；文本 IR 可以把它写在结果类型上，两者仍对应同一含义。

加乘不做隐式广播，bool 加乘无定义。i32/i64 的正向加乘沿用显式 wrap 语义；存在正向类型规则，不表示该类型有浮点求导规则。

## 2. 反向规则生成基础图

通用 VJP 调度器负责依赖顺序、累计贡献和遍历操作，再调用对应的 `rule.vjp`。例如 `z = x * y` 的规则生成：

```text
dx = mul(dz, y)
dy = mul(dz, x)
```

它调用 builder.mul 创建 SSA 操作，没有在 Python 上计算张量数值。生成的 mul 再次受同一套抽象求值和求导规则约束；高阶变换因此能继续展开。

分发入口检查原值与操作输入类型一致、cotangent 与结果一致、返回数量与输入数一致，以及每个梯度的 shape/dtype。一个输入收到多条贡献时，由调度器用 add 累加。

规则内部的 None 表示已知的结构性零，例如不参与本次求导的输入；它不是未知导数。这个内部约定不改变用户 fun.backward 的契约：用户方法仍必须返回完整梯度 tuple，不能用 None 冒充缺失规则。

## 3. 前向模式也由规则生成图

JVP 为输入给定切向量。例如乘法生成 `dz = dx*y + x*dy`，其中每一步仍是已注册的 add/mul。这个变换用于编译器内部组合与验证，公开 Tensor 接口仍是 backward。

```python
from fugatensor import ir

module = ir.Module()
t = ir.TensorType((3,), "f32")
graph = module.graph("square", inputs={"x": t})
graph.return_(graph.mul(graph.inputs["x"], graph.inputs["x"]))

forward = ir.jvp(module, argnums=(0,))
reverse = ir.vjp(module, argnums=(0,))
forward.verify()
reverse.verify()
```

`ir.jvp` 当前接受单函数 Module，参数依次是原输入和所选输入的 tangent；结果依次是全部原输出和全部输出 tangent。上例输入 x、dx，输出 x*x、2*x*dx。`argnums` 省略时选择全部浮点输入；显式顺序决定新增切向量端口顺序。

`ir.vjp` 的参数是原输入加输出 cotangent，结果是所选输入梯度。二者都要求需要变换的输入输出为浮点，执行所需的 Tensor 形状具体明确。静态 region 先特化，数据依赖 region 不会被偷偷当作常量。

## 4. 当前规则范围

| 操作 | 类型/形状 | VJP | JVP |
|---|---|---|---|
| constant | 显式 dtype 和字面值 | 无输入梯度 | 零切向量 |
| splat | 标量变为指定 shape | 对活跃标量输入反传需要尚未实现的归约 | 可把标量 tangent splat 到结果形状 |
| add | 两侧类型完全一致 | 把 cotangent 送往活跃输入 | 两侧 tangent 相加 |
| mul | 两侧类型完全一致 | cotangent 乘以另一侧原值 | 两个乘积相加 |
| cast | 保留 shape，显式目标 dtype | 浮点 cotangent 转回输入 dtype | 浮点 tangent 转为输出 dtype |
| external | 独立实现协议检查 | 活跃路径缺少规则时拒绝 | 活跃路径缺少规则时拒绝 |
| fun call | 验证前向签名和保存值 | 可见输出用手写 backward，隐藏保存值递归 VJP | 活跃 call 当前拒绝，手写 VJP 不等于 JVP |

浮点 cast 的规则忽略量化舍入；整数/bool cast 在活跃求导路径上拒绝。JVP/VJP 可保留不参与求导的外部系数计算，不为未知导数编造规则。

## 5. 高阶请求需要再次检查

`backward(create_graph=True)` 检查需要的正向与生成的反向，梯度图保留 fun call，执行降到 ASK 时才展开。每一阶对可见输出仍选择手写 VJP；隐藏保存值的 cotangent 则从 forward 投影出相应 SSA 计算，再递归 VJP，其中的嵌套 call 也保留自己的规则。两路同时存在时累加，不能为得到平坦图而绕过自定义语义。

原始输入、保存值、显式梯度种子与累计加法都要保持依赖；缓存计划还要验证反向图及嵌套定义，防止已有正向历史与修改后的反向规则混用。

不透明 Triton 正向或反向在这一阶段提前报错，即使一阶 backward 已有手写规则。当前可组合规则只覆盖目录中的基础运算，不是对任意 DSL 的自动解析或任意程序的数学可微性证明。

以后增加原子算子，需要一起提供抽象求值、需要支持的变换规则及对应 ASK 执行语义，再检查组合后的形状、数值和多阶结果。缺少任一条支持路径时应明确拒绝，不能仅把算子名字加入目录就宣称可求导。

规则与 IR 构建当前仍在 Python；C++ 核心负责拓扑、依赖和活跃性分析。后续迁移实现语言时应保留这些契约，避免为 CPU、CUDA 或某个第三方编译器再复制一套求导语义。
