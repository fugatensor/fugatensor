# FugaTensor 安装

返回文档目录：[文档目录](README.md) · 相关细节：[ASK 桥接与多后端执行](architecture/04-ASK桥接与多后端执行.md#bootstrap-and-config)

ASK 是 FugaTensor 必需的运行依赖，负责实际图编译与算术执行。两个项目分别构建，再将产物安装到同一运行环境；构建 FugaTensor 自身不需要安装 ASK，也不读取 ASK 源码。安装和运行均不要求存在同级 `../ask` 目录。本文中的 `/absolute/path/...` 须替换为实际路径；没有假定这些项目已经发布到 PyPI。

<a id="requirements"></a>

## 1. 版本与环境要求

当前 `fugatensor==0.1.0` 的包元数据要求 Python 3.10+ 和 `ask-compiler==0.1.0`。两者都包含原生扩展，wheel 必须匹配当前 Python ABI、操作系统及架构；现有 ASK SDK 与构建验证面向 Linux x86-64，不能据此推定其它平台可用。

| 使用方式 | 额外要求 |
| --- | --- |
| 从两个 wheel 安装并运行 CPU 图 | 可执行 `cc -shared` 的 C 工具链，用于首次 JIT 时把 ASK 生成的目标文件链接为动态库。运行不需要 LLVM SDK、ASK 源码树或 `engine.json`。 |
| 独立构建 FugaTensor wheel | C++17 编译器、Python 开发头文件、CMake 3.28+ 与构建工具。隔离构建安装 `pyproject.toml` 声明的 scikit-build-core / nanobind；FugaTensor 的 C++ 扩展构建不依赖已安装的 ASK、LLVM、CUDA 或 ASK 头文件。 |
| CUDA 执行 | 可用的 NVIDIA 驱动、与 ASK LLVM 契约匹配的 `llc`、支持目标架构与 PTX 的 `ptxas`，并显式配置工具路径。 |

<a id="build-ask"></a>

## 2. 阶段 A：在 ASK 项目中构建 ASK wheel

先独立准备 `ask-compiler==0.1.0` 的兼容 wheel。ASK 的编译器构建需要其锁定的 LLVM/MLIR SDK，由 ASK 自己的构建流程管理。已有构建者提供的兼容 wheel 时可直接进入阶段 B；这只是跳过本地构建，运行时仍必须安装 ASK。

以下命令在 ASK 自己的构建环境中运行，路径可与 FugaTensor 完全无关：

```bash
python3 /absolute/path/to/ask/tools/fetch_deps.py
python3 -m pip wheel --no-deps /absolute/path/to/ask \
  --wheel-dir /absolute/path/to/ask-wheel-output
```

默认产生核心 ASK 包，包含自有 CPU/CUDA 路径。需要 Triton 适配器时，应在这一阶段按 ASK 的构建选项生成带适配器的包；安装 FugaTensor 不会改变 ASK 的编译配置。完整说明见可选源码链接 [ASK 安装](../../ask/docs/安装.md)；不需要把 ASK 放在 FugaTensor 的同级目录。

<a id="build-fugatensor"></a>

## 3. 阶段 B：在 FugaTensor 项目中构建 FugaTensor wheel

在 FugaTensor 自己的构建环境中执行：

```bash
python3 -m pip wheel --no-deps /absolute/path/to/fugatensor \
  --wheel-dir /absolute/path/to/fuga-wheel-output
```

`--no-deps` 避免构建前端尝试解析或构建运行依赖 ASK。此时可以完全没有安装 ASK，也不需要它的源码树或 LLVM SDK；生成的 FugaTensor wheel 仍声明必需的 `ask-compiler==0.1.0` 运行依赖。隔离构建所需的 Python 包须能从配置的包源或本地 wheel 目录获取。

若使用 `build` 前端，安装 `build==1.3.0` 后可运行 `python3 -m build --wheel --outdir /absolute/path/to/fuga-wheel-output /absolute/path/to/fugatensor`，同样只构建 FugaTensor 自身。

<a id="install-wheels"></a>

## 4. 阶段 C：安装两个 wheel 并运行

准备兼容的 ASK 和 FugaTensor wheel。可由构建者提供或由各项目源码构建；只需传入实际产物路径，不要求两个源码仓库并列存放。

```bash
python3 -m venv /absolute/path/to/fuga-env
source /absolute/path/to/fuga-env/bin/activate

# 填入实际 wheel 的完整文件名
ask_wheel='/absolute/path/to/ask_compiler-0.1.0-<python>-<abi>-<platform>.whl'
fuga_wheel='/absolute/path/to/fugatensor-0.1.0-<python>-<abi>-<platform>.whl'
python -m pip install --no-index "$ask_wheel" "$fuga_wheel"
python -m pip check
```

以上命令只从指定文件安装。核心 ASK wheel 已包含 Python SDK、`ask._native` 和伴生 `ask-opt`，CPU 路径会自动找到配套 CLI。C/C++ 工具链和 GPU 工具不是 Python wheel 的运行依赖，须按实际使用路径准备。

开发 FugaTensor 时，在已安装兼容 ASK 包的环境中也可执行 `python -m pip install --no-deps -e /absolute/path/to/fugatensor`，随后运行 `python -m pip check`。该命令只构建、安装 FugaTensor，不会重编 ASK。

<a id="verify-cpu"></a>

## 5. 在源码目录之外验收 CPU 安装

保持虚拟环境激活，切换到任意非源码目录，用隔离模式执行实际 JIT 计算。此步骤不需要 `PYTHONPATH`、`ASK_OPT` 或 `FUGATENSOR_CONFIG`；若环境中设置了这些变量，下面的命令将其移除，避免误用其它安装。

```bash
cd /tmp
env -u PYTHONPATH -u PYTHONHOME -u ASK_OPT -u FUGATENSOR_CONFIG python -I - <<'PY'
from importlib.metadata import version
import ask
import fugatensor as ft

assert version("ask-compiler") == ask.__version__ == "0.1.0"
assert version("fugatensor") == "0.1.0"

@ft.jit
def arithmetic(x, y):
    return (x + y) * 2

with ft.Engine(device="cpu") as engine:
    x = engine.tensor([1, 2], dtype="f32")
    y = engine.tensor([10, 20], dtype="f32")
    result = arithmetic(x, y).tolist()
    assert result == [22.0, 44.0], result
    print(result)
    print("ASK:", ask.__file__)
    print("FugaTensor:", ft.__file__)
PY
```

若系统中的链接器不叫 `cc`，在 `ft.Engine` 或 `ft.configure` 中传入 `cc="/absolute/path/to/cc"`。当前实现没有 `FUGATENSOR_CC` 环境变量入口。

<a id="configure-cuda"></a>

## 6. 配置自有 CUDA 路径

核心 ASK 包已包含自有 CUDA 降级和设备运行时，不需要安装 Triton。CUDA 编译仍需独立的 `llc` 和 `ptxas` 可执行文件，执行需能加载 NVIDIA Driver 的 `libcuda.so.1`。`llc` 应来自与 ASK 使用的 LLVM 版本、修订匹配的工具链，可放在任意工具目录；通过 `ask.Compiler().capabilities()` 查询 `llvm_version` 与 `llvm_revision`。保留工具不等于保留 ASK 源码树。

```python
import fugatensor as ft

ft.configure(
    device="cuda",
    llc="/absolute/path/to/llvm/bin/llc",
    ptxas="/absolute/path/to/cuda/bin/ptxas",
)
x = ft.tensor([1, 2], dtype="f32", device="cuda")
assert (x * 2 + 1).tolist() == [3.0, 5.0]
ft.shutdown()
```

也可设置 `FUGATENSOR_LLC`、`FUGATENSOR_PTXAS` 环境变量，再使用默认 CUDA 引擎。仅把工具放进 `PATH` 不会自动填充这两项引擎配置。CPU 验收通过不代表驱动、CUDA 编译或物理 GPU 执行已经验证。

<a id="configure-triton"></a>

## 7. 可选的 Triton 融合

使用用户 Triton kernel 时，需要满足三项条件：ASK 包构建时已经启用 `triton` 适配器、worker 的 Python 环境安装 Triton 3.7.1、CUDA 工具和驱动已就绪。单独安装 Triton 不会给核心 ASK 包增加适配器；应安装带该适配器的 ASK wheel，仍须满足 `ask-compiler==0.1.0`。

若 worker 与宿主使用同一个虚拟环境：

```bash
python -m pip install triton==3.7.1
```

worker 与 `fusion.py`、锁文件等资源随适配器 ASK wheel 安装。配置应指向包内资源，无需指向源码仓库：

```python
from pathlib import Path
import sys
import ask
from ask import Compiler, CompilerEnvironment
import fugatensor as ft

assert "triton" in Compiler().capabilities()["third_party_compilers"]
worker = Path(ask.__file__).resolve().parent / "share/ask/adapters/triton/worker.py"
assert worker.is_file(), worker

ft.configure(
    device="cuda",
    llc="/absolute/path/to/llvm/bin/llc",
    ptxas="/absolute/path/to/cuda/bin/ptxas",
    compilers={"triton": CompilerEnvironment(python=sys.executable, worker=worker)},
)
```

worker 也可位于独立 Python 环境：将 `python=sys.executable` 换成安装 Triton 3.7.1 的解释器绝对路径即可。使用环境变量时，`FUGATENSOR_TRITON_PYTHON` 和 `FUGATENSOR_TRITON_WORKER` 必须同时设置。具体 kernel 注册示例见 [README](../README.md)。

## 8. 可选的开发环境引导

`tools/bootstrap.py` 需要 Python 3.11+，只配置 FugaTensor 开发环境。ASK 必须作为独立构建的 wheel 或目标虚拟环境中已安装的包提供；脚本不会读取 ASK 源码、获取 LLVM SDK 或编译 ASK。使用两个 wheel 安装运行时无需执行此脚本。

```bash
# ask_wheel 使用阶段 C 中填好的实际 ASK wheel 路径
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env --ask-wheel "$ask_wheel"

# 目标环境已安装兼容 ASK 时，省略 --ask-wheel，仅更新 FugaTensor
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env
```

脚本检查必需的 ASK 版本、原生扩展与伴生 CLI 能力，准备 FugaTensor 自己的构建依赖，可编辑安装 FugaTensor，并执行 `pip check`。首次 CPU 引导无需 SDK，会写入 `llc = null`、`ptxas = null`、`compilers = {}` 的 `share/fugatensor/engine.json`。

需要由脚本记录 CUDA/Triton 配置时，先独立安装启用了 Triton 适配器的 ASK wheel，并准备好含 Triton 3.7.1 的 worker 环境，再显式传入工具：

```bash
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env \
  --llvm-root /absolute/path/to/llvm-sdk \
  --ptxas /absolute/path/to/cuda/bin/ptxas \
  --compiler-python triton=/absolute/path/to/triton-env/bin/python
```

这里只使用自有 CUDA 时省略 `--compiler-python`。`--llvm-root` 要求 SDK 中的 `bin/llc` 可执行且 `VCSRevision.h` 与安装的 ASK 修订一致；`--compiler-python` 仅配置已经启用的适配器，读取 ASK 包内的注册表、worker 和依赖锁检查所选环境，不会安装 Triton 或改变 ASK 构建。

再次执行且没有指定工具/worker 参数时，脚本会保留已有 `engine.json`，校验其格式、适配器 ID 与包内 worker 路径。指定任一 `--llvm-root`、`--ptxas`、`--compiler-python` 会按本次参数整体重写配置，需同时传入仍要使用的其它工具。`--reset-config` 可显式清空旧配置；更换 ASK 后若旧配置引用了未启用的适配器，会报错要求重置或重新配置。

旧的 `--ask-root`、`--compilers`、`--skip-ask` 联合构建参数会被拒绝；ASK 构建与适配器选择应在阶段 A 完成。包安装本身无需 `engine.json`；配置读取规则见 [ASK 桥接与多后端执行](architecture/04-ASK桥接与多后端执行.md#bootstrap-and-config)。

文档中的 `../../ask/...` 等跨仓相对链接仅用于在源码并列检出时浏览实现说明，不参与安装或执行。可选参考：[ASK 安装](../../ask/docs/安装.md)、[ASK 版本契约](../../ask/docs/02-前端接入与构建配置.md#version-contract)。
