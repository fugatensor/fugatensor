# FugaTensor 安装

返回文档目录：[文档目录](README.md) · 相关细节：[ASK 桥接与多后端执行](architecture/ASK桥接与多后端执行.md#bootstrap-and-config)

安装已有 wheel 可直接看第 4 节。从源码构建时，先安装 ASK SDK，再构建 FugaTensor。文中的 `/absolute/path/...` 请替换为实际路径。

<a id="requirements"></a>

## 1. 版本与环境要求

FugaTensor 0.1.0 的 pure 安装要求 Python 3.10+，all 要求 Python 3.11+ 和 Triton 支持的平台。源码构建使用 ASK SDK 0.1.0。wheel 须匹配 Python ABI、操作系统和架构；目前验证的平台为 Linux x86-64。

| 使用方式 | 额外要求 |
| --- | --- |
| 安装 wheel 并运行 CPU 图 | 支持 `cc -shared` 的 C 工具链，用于 JIT 链接目标文件。 |
| 从源码构建 FugaTensor | ASK SDK、C++17 编译器、Python 开发头文件、CMake 3.28+ 和构建工具。Python 构建依赖见 `pyproject.toml`。 |
| 自行构建 ASK SDK | ASK 支持的同系列 LLVM/MLIR 稳定版 SDK 与 C++ 构建工具，依赖获取和构建由 ASK 项目负责。 |
| CUDA 执行 | NVIDIA 驱动和设备。自有计算使用与 ASK 构建版本匹配的 `llc`、支持目标 PTX 的 `ptxas`；第三方计算使用对应 worker。 |

<a id="build-ask"></a>

## 2. 在 ASK 项目中安装 C++ SDK

在 ASK 源码目录构建并安装 SDK：

```bash
cd /absolute/path/to/ask
python3 tools/fetch_deps.py
cmake --preset core -DCMAKE_INSTALL_PREFIX=/absolute/path/to/ask-sdk
cmake --build --preset core
cmake --install build/core
/absolute/path/to/ask-sdk/bin/ask-opt --capabilities
```

FugaTensor 链接 SDK 中的 `libask_compiler.so` 和 `libask_runtime.so`。其他安装选项见 [ASK 安装](../../ask/docs/安装.md)。

<a id="install-fuga-source"></a>
<a id="build-fugatensor"></a>

## 3. 构建 FugaTensor wheel

将已安装 SDK 的前缀传给 CMake：

```bash
CMAKE_PREFIX_PATH=/absolute/path/to/ask-sdk \
  python3 -m pip wheel --no-deps /absolute/path/to/fugatensor \
  --wheel-dir /absolute/path/to/fuga-wheel-output
```

pip 会安装 `pyproject.toml` 声明的 scikit-build-core 和 nanobind，再用 SDK 头文件及共享库构建扩展。生成的 wheel 将 ASK 共享库放在 `fugatensor/_lib/`。

开发时可改用可编辑安装：

```bash
CMAKE_PREFIX_PATH=/absolute/path/to/ask-sdk \
  python -m pip install -e '/absolute/path/to/fugatensor[pure]'
python -m pip check
```

将 `[pure]` 改为 `[all]` 可同时安装 Triton。

<a id="install-wheels"></a>
<a id="installation-variants"></a>

## 4. 安装 FugaTensor wheel

`pure` 和 `all` 是同一发行包的标准可选依赖：

| 安装命令 | 依赖与用途 |
| --- | --- |
| `python -m pip install 'fugatensor[pure]'` | 基础依赖，适用于 CPU 和 ASK 自有 CUDA 计算；等同直接安装 `fugatensor`。 |
| `python -m pip install 'fugatensor[all]'` | 自动安装 `triton>=3.9,<3.10`，用于用户 Triton 算子和内置 attention。Python 与平台须满足 Triton 要求。 |

两种选择共用 wheel，包含 C++ 扩展、ASK 共享库和适配器源码。已有 Triton 的环境可直接使用该编译器。all 在 Python 或平台不兼容时安装失败。

安装本地构建的 wheel 时，在完整路径后选择对应 extra：

```bash
python3 -m venv /absolute/path/to/fuga-env
source /absolute/path/to/fuga-env/bin/activate

# 填入实际 wheel 的完整文件名
fuga_wheel='/absolute/path/to/fugatensor-0.1.0-<python>-<abi>-<platform>.whl'
python -m pip install "${fuga_wheel}[pure]"
# 使用 Triton 时，将上一行的 [pure] 改为 [all]
python -m pip check
```

all 由 pip 解析并安装 Triton；离线安装请提前准备兼容的 Triton wheel。链接器和 CUDA 工具按后续章节配置。

<a id="verify-cpu"></a>

## 5. 在源码目录之外验收 CPU 安装

在虚拟环境中切换到 `/tmp`，检查安装后的 JIT 计算：

```bash
cd /tmp
env -u PYTHONPATH -u PYTHONHOME -u ASK_OPT -u FUGATENSOR_CONFIG python -I - <<'PY'
from importlib.metadata import version
import fugatensor as ft

print("Version:", version("fugatensor"))  # 0.1.0
def arithmetic(x, y):
    return (x + y) * 2

x = ft.tensor([1, 2])
y = ft.tensor([10, 20])
result = arithmetic(x, y).tolist()
print(result)  # [22.0, 44.0]
print("FugaTensor:", ft.__file__)
PY
```

使用其他链接器时，在创建张量前调用 `ft.configure(cc="/absolute/path/to/cc")`。常规用法见 [API](API/README.md)。

<a id="configure-cuda"></a>

## 6. 配置自有 CUDA 路径

自有 CUDA 计算使用 `llc` 生成 PTX、`ptxas` 生成 cubin，再由 NVIDIA 驱动执行。`llc --version` 须与 ASK 的 `ask-opt --capabilities` 中的 `llvm_version` 一致。

```python
import fugatensor as ft

ft.configure(
    device="cuda",
    llc="/absolute/path/to/llvm/bin/llc",
    ptxas="/absolute/path/to/cuda/bin/ptxas",
)
x = ft.tensor([1, 2], device="cuda")
print((x * 2 + 1).tolist())  # [3.0, 5.0]
```

工具路径也可通过 `FUGATENSOR_LLC`、`FUGATENSOR_PTXAS` 提供。默认设备由 `ft.set_default_device("cuda")` 设置；`configure` 设置工具和运行选项。

<a id="configure-triton"></a>

## 7. 可选的 Triton 编译环境

all 默认用当前 Python 环境运行包内 Triton worker。图中含 ASK 自有计算时，另按上一节配置 `llc` / `ptxas`。

支持 Triton 3.9.x 稳定版，已验证 3.9.0。版本基线和 ABI 见 [`triton.dependencies.lock.json`](../src/fugatensor/triton.dependencies.lock.json)，缓存记录实际编译器和工具信息。

使用独立 Python 3.11+ 环境编译 Triton 时：

```bash
/path/to/triton-env/bin/python -m pip install 'triton>=3.9,<3.10'
```

```python
import fugatensor as ft

ft.configure(
    device="cuda",
    llc="/absolute/path/to/llvm/bin/llc",
    ptxas="/absolute/path/to/cuda/bin/ptxas",
    compilers={"triton": ft.triton.environment(python="/path/to/triton-env/bin/python")},
)
```

Python 3.10 的宿主可通过上述配置使用独立 worker；`from_jit` 则要求宿主环境满足 Triton 的版本要求。也可用 `FUGATENSOR_TRITON_PYTHON` 指定解释器、`FUGATENSOR_TRITON_WORKER` 指定 worker。配置优先级见[配置规则](architecture/ASK桥接与多后端执行.md#bootstrap-and-config)，注册方法见 [README](../README.md)。

<a id="source-bootstrap"></a>

## 8. 开发环境引导

`tools/bootstrap.py` 使用 Python 3.11+ 和已安装的 ASK SDK，创建虚拟环境、安装构建依赖，再进行可编辑安装。默认选 pure，`--variant all` 同时安装 Triton。

```bash
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env \
  --ask-prefix /absolute/path/to/ask-sdk \
  --variant pure
```

脚本检查 SDK 版本和编译能力，通过 `CMAKE_PREFIX_PATH` 配置构建，最后运行 `pip check`，将工具配置写入 `share/fugatensor/engine.json`。

同时配置 CUDA 工具和独立 worker 时：

```bash
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env \
  --ask-prefix /absolute/path/to/ask-sdk \
  --llvm-root /absolute/path/to/llvm-sdk \
  --ptxas /absolute/path/to/cuda/bin/ptxas \
  --compiler-python triton=/absolute/path/to/triton-env/bin/python
```

`--llvm-root` 检查 `bin/llc` 与 ASK 的构建版本，`--compiler-python` 检查独立 worker 的 Triton 版本。使用默认 worker 时省略 `--compiler-python`。

再次执行且没有工具/worker 参数时，脚本保留已有 `share/fugatensor/engine.json`。指定任一 `--llvm-root`、`--ptxas`、`--compiler-python` 会按本次参数整体重写配置，需同时传入仍要使用的其它工具；`--reset-config` 可清空旧配置。配置读取规则见 [ASK 桥接与多后端执行](architecture/ASK桥接与多后端执行.md#bootstrap-and-config)。
