# FugaTensor 安装

返回文档目录：[文档目录](README.md) · 相关细节：[ASK 桥接与多后端执行](architecture/04-ASK桥接与多后端执行.md#bootstrap-and-config)

ASK 提供 C++ 编译器与运行时 SDK，FugaTensor 提供 Python API 和原生绑定。先独立安装 ASK SDK，再用它构建 FugaTensor wheel；wheel 包含运行所需的 ASK 共享库。安装和运行不要求两个源码仓库并列存放，也不安装 ASK Python 包。本文中的 `/absolute/path/...` 须替换为实际路径。

<a id="requirements"></a>

## 1. 版本与环境要求

当前 FugaTensor 0.1.0 要求 Python 3.10+，原生构建精确匹配 ASK SDK 0.1.0。wheel 必须匹配 Python ABI、操作系统及架构；现有构建验证面向 Linux x86-64。

| 使用方式 | 额外要求 |
| --- | --- |
| 安装 FugaTensor wheel 并运行 CPU 图 | 可执行 `cc -shared` 的 C 工具链，用于首次 JIT 时链接目标文件；不需要 ASK SDK、LLVM SDK 或源码。 |
| 从源码构建 FugaTensor | 已安装的 ASK SDK、C++17 编译器、Python 开发头文件、CMake 3.28+ 与构建工具。Python 构建依赖由 `pyproject.toml` 锁定；消费 ASK 的 Compiler / Runtime 组件不需要 LLVM SDK。 |
| 自行构建 ASK SDK | ASK 锁定的 LLVM/MLIR SDK 与 C++ 构建工具，依赖获取和构建由 ASK 项目负责。 |
| CUDA 执行 | 可用的 NVIDIA 驱动。自有计算另需与 ASK LLVM 契约匹配的 `llc` 和支持目标 PTX 的 `ptxas`；第三方编译器使用各自 worker 环境。 |

<a id="build-ask"></a>

## 2. 在 ASK 项目中安装 C++ SDK

已有兼容 SDK 时可直接进入下一节。自行构建时，在 ASK 源码目录执行：

```bash
cd /absolute/path/to/ask
python3 tools/fetch_deps.py
cmake --preset core -DCMAKE_INSTALL_PREFIX=/absolute/path/to/ask-sdk
cmake --build --preset core
cmake --install build/core
/absolute/path/to/ask-sdk/bin/ask-opt --capabilities
```

安装目录包含 `include/ask/`、`lib/libask_compiler.so`、`lib/libask_runtime.so`、`lib/cmake/ASK/` 和 `bin/ask-opt`。FugaTensor 通过 CMake 的 `ASK::Compiler`、`ASK::Runtime` 链接这两个共享库。Triton worker 由 FugaTensor 提供，无需按第三方编译器重新构建 ASK。详细构建说明见 [ASK 安装](../../ask/docs/安装.md)。

<a id="install-fuga-source"></a>
<a id="build-fugatensor"></a>

## 3. 构建 FugaTensor wheel

将已安装 SDK 的前缀传给 CMake：

```bash
CMAKE_PREFIX_PATH=/absolute/path/to/ask-sdk \
  python3 -m pip wheel --no-deps /absolute/path/to/fugatensor \
  --wheel-dir /absolute/path/to/fuga-wheel-output
```

构建使用 SDK 的公开头文件与共享库，不读取 ASK 源码。隔离构建会安装 `pyproject.toml` 声明的 scikit-build-core / nanobind；这些构建依赖须能从配置的包源或本地 wheel 目录获取。ASK 共享库随生成的 FugaTensor wheel 安装到 `fugatensor/_lib/`，与 FugaTensor 的 `_native` 扩展配套。

开发时可改用可编辑安装：

```bash
CMAKE_PREFIX_PATH=/absolute/path/to/ask-sdk \
  python -m pip install --no-deps -e /absolute/path/to/fugatensor
python -m pip check
```

<a id="install-wheels"></a>

## 4. 安装 FugaTensor wheel

```bash
python3 -m venv /absolute/path/to/fuga-env
source /absolute/path/to/fuga-env/bin/activate

# 填入实际 wheel 的完整文件名
fuga_wheel='/absolute/path/to/fugatensor-0.1.0-<python>-<abi>-<platform>.whl'
python -m pip install --no-index "$fuga_wheel"
python -m pip check
```

运行环境不需要保留 SDK 安装目录。默认编译和执行通过 FugaTensor 的原生扩展直接调用 ASK C++；C/C++ 链接器及 GPU 编译工具仍按实际使用路径单独准备。

<a id="verify-cpu"></a>

## 5. 在源码目录之外验收 CPU 安装

保持虚拟环境激活，切换到非源码目录，用隔离模式执行实际 JIT 计算：

```bash
cd /tmp
env -u PYTHONPATH -u PYTHONHOME -u ASK_OPT -u FUGATENSOR_CONFIG python -I - <<'PY'
from importlib.metadata import version
import fugatensor as ft

assert version("fugatensor") == "0.1.0"
def arithmetic(x, y):
    return (x + y) * 2

with ft.Engine(device="cpu") as engine:
    x = engine.tensor([1, 2], dtype="f32")
    y = engine.tensor([10, 20], dtype="f32")
    result = arithmetic(x, y).tolist()
    assert result == [22.0, 44.0], result
    print(result)
    print("FugaTensor:", ft.__file__)
PY
```

链接器不叫 `cc` 时，在 `ft.Engine` 或 `ft.configure` 中传入 `cc="/absolute/path/to/cc"`。没有 `FUGATENSOR_CC` 环境变量入口。

<a id="configure-cuda"></a>

## 6. 配置自有 CUDA 路径

自有 CUDA 降级和设备运行时随 ASK 共享库提供，不需要 Triton。CUDA 编译需要独立的 `llc` 和 `ptxas` 可执行文件，执行需要 NVIDIA Driver。`llc` 应与构建 ASK 使用的 LLVM 版本、修订匹配；SDK 的 `ask-opt --capabilities` 会报告 `llvm_version` 与 `llvm_revision`。

```python
import fugatensor as ft

ft.configure(
    device="cuda",
    llc="/absolute/path/to/llvm/bin/llc",
    ptxas="/absolute/path/to/cuda/bin/ptxas",
)
x = ft.tensor([1, 2], dtype="f32", device="cuda")
assert (x * 2 + 1).tolist() == [3.0, 5.0]
ft.shutdown()
```

也可设置 `FUGATENSOR_LLC`、`FUGATENSOR_PTXAS` 环境变量。仅把工具放进 `PATH` 不会填充这两项配置。CPU 验收通过不代表 GPU 执行已经验证。

<a id="configure-triton"></a>

## 7. 可选的 Triton 编译环境

使用 Triton kernel 时，为 worker 准备安装 Triton 3.7.1 的 Python 环境。FugaTensor 自带薄适配器，读取编译器产物及启动元数据，由 ASK 调度；两者无需共用 LLVM。包含 ASK 自有计算时，还须按上一节配置 `llc` / `ptxas`。

```bash
/path/to/triton-env/bin/python -m pip install triton==3.7.1
```

```python
import fugatensor as ft

ft.configure(
    device="cuda",
    llc="/absolute/path/to/llvm/bin/llc",
    ptxas="/absolute/path/to/cuda/bin/ptxas",
    compilers={"triton": ft.triton.environment(python="/path/to/triton-env/bin/python")},
)
```

worker 可与宿主共用环境，也可独立安装。`FUGATENSOR_TRITON_PYTHON` 设置 worker 解释器，`FUGATENSOR_TRITON_WORKER` 可覆盖包内 worker 路径。仅运行外部 kernel 时可省略 ASK 的 `llc` / `ptxas`。具体注册方法见 [README](../README.md)。

<a id="source-bootstrap"></a>

## 8. 开发环境引导

`tools/bootstrap.py` 需要 Python 3.11+。它接受已安装的 ASK SDK，为 FugaTensor 创建或复用隔离虚拟环境、安装构建依赖并进行可编辑安装；不编译 ASK，也不安装第三方编译器。

```bash
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env \
  --ask-prefix /absolute/path/to/ask-sdk
```

脚本核对 SDK 头文件、CMake 版本元数据与 `ask-opt` 能力，随后通过 `CMAKE_PREFIX_PATH` 将 SDK 交给 FugaTensor 构建，最后执行 `pip check`。CMake 检查精确版本与共享库。首次 CPU 引导写入空的 GPU 工具配置。

需要记录 CUDA/Triton 配置时，显式提供工具和已准备好的 worker 环境：

```bash
python3 /absolute/path/to/fugatensor/tools/bootstrap.py \
  --venv /absolute/path/to/fuga-dev-env \
  --ask-prefix /absolute/path/to/ask-sdk \
  --llvm-root /absolute/path/to/llvm-sdk \
  --ptxas /absolute/path/to/cuda/bin/ptxas \
  --compiler-python triton=/absolute/path/to/triton-env/bin/python
```

仅用自有 CUDA 时省略 `--compiler-python`。`--llvm-root` 检查 `bin/llc` 和 `VCSRevision.h` 与 ASK 修订匹配；`--compiler-python` 按 FugaTensor 依赖锁验证 Triton 版本。

再次执行且没有工具/worker 参数时，脚本保留已有 `share/fugatensor/engine.json`。指定任一 `--llvm-root`、`--ptxas`、`--compiler-python` 会按本次参数整体重写配置，需同时传入仍要使用的其它工具；`--reset-config` 可清空旧配置。配置读取规则见 [ASK 桥接与多后端执行](architecture/04-ASK桥接与多后端执行.md#bootstrap-and-config)。
